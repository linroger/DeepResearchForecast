## Blocking contracts and precise amendments

### D1 — P1: query arguments cannot grant reader authority
**Conflict:** II.4 exposes `(classes_allowed, as_of_period, actor_scope)` and grants `analyst` everything (P:62–66). An actor choosing `analyst` or requesting `forecast` would bypass I-1/I-30. An estimator or writer with that same unrestricted role could also consume simulation-derived data despite RW-11. SQL views alone do not establish caller authorization.
**Amend:** Define I-1's subject as simulation actor principals; forecasting/writing agents receive separate, narrowed analysis capabilities. Bind an immutable reader capability in the host: role/step, run, generation, actor, path, clock and maximum permitted classes/fields. Query arguments MAY only narrow it. Actor tools MUST NOT accept role escalation, direct base-table SQL, raw `agent_io`, or bypass retrieval paths. Writer capabilities likewise determine classes; an agent cannot label its own output `observed` or `actor_known`.
**Acceptance:** Every query, join, aggregate, retrieval projection and cache hit rejects widening/foreign IDs; actor attempts to request `analyst`, forecasts or another actor's private data fail closed. Estimator/narrative roles have narrower capabilities than an administrative inspector. These are integrity errors, not grade-only epistemic shortfalls.
**Owner:** B1/API owner; decide before B1 contract approval.

### D2 — P1: class, knowledge basis and actor self-inference are different axes
**Conflict:** R-08's item `class=actor_known|analyst_inferred` is not II.1's `record_class` (P:40–47,115). I-30 says “as its own knowledge,” while II.4 absolutely excludes inferred self-claims. S-00/S-02/S-05 also create beliefs and self-assessments, with no declared class/visibility rule. Current legacy tests explicitly permit labeled own-actor analyst inference in the user dossier (`test_context_audit_simulation.py:234–243`); that is not proof of the draft's stronger ban.
**Amend:** Separate `record_class`, `knowledge_basis`, producer, subject and visibility. Recommend strict II.4 for actor inputs: analyst-authored self-inference MUST NOT enter the actor payload, including labeled dossier text or transformed summaries. An actor MAY infer from its admitted observations; persist that result as `simulated`, actor-generated, owner-private and path-scoped, with consumed-input lineage. It does not become observed fact, actor-known research or a published forecast. Reject actor-requested reclassification.
**Acceptance:** Inject an analyst self-claim through dossier, graph, summary, cache and alias paths: absent from all actor input channels. Actor-generated belief updates remain visible only to that actor/path; foreign private beliefs and first-party forecast records remain excluded. A quoted third-party forecast is an observed statement with attribution, not observed truth or our forecast authority.
**Owner:** B1 plus actor-intelligence owner; explicitly ratify the strict interpretation before B1/C5.

### D3 — P1: period alone cannot define date, identity or path scope
**Gap:** Common row fields omit generation/path/owner and the query signature lacks a path (P:52,62). Claim fields have observation/publication dates but no uniform release/vintage contract (P:422). `observed → everyone` is not a permission rule; release time alone does not make privately known information public.
**Amend:** Use stable scoped record/entity IDs, a frozen run generation and explicit shared-snapshot versus path-local ownership. Preserve source availability/publication, retrieval/vintage, effective date and actor observation/release time separately. Both frozen research-cutoff admission and simulated observation-time admission MUST hold; a future scheduled event known before cutoff is distinguishable from a future release not yet known. Unknown availability cannot silently mean public/current. Filesystem paths and fuzzy aliases MUST NOT establish identity or access.
**Acceptance:** Reject same actor/record IDs from another run, generation or path; reject a later vintage or hidden record through a join. Test immediately before/at/after release plus lag, a known future calendar entry, revised data and missing dates. Forks retain source lineage but cannot read parent-private path state; scope fingerprints bind cached results and observation digests.
**Owner:** B1/schema owner; decide before schemas and SQL views are frozen. ADR 0002:23–39 is the identity/provenance authority.

### D4 — P1: live DB and resumable exports need one generation authority
**Conflict:** “Every phase reads/writes one store” coexists with exports that resume/replay read (P:19,52–54). B1's round-trip/export/call-replay tests do not decide which generation wins after a DB commit/export crash. “One workflow” also risks silently overriding ADR 0001's separately gated workflow-authority cutover.
**Amend:** B1 initially adds the typed evidence/model store under the existing controller; it MUST NOT acquire workflow advancement merely by using SQLite. Commit validated rows and a generation watermark atomically. Seal exports from that exact snapshot, with deterministic row order and a versioned canonical JSON/number/date profile; publish the manifest only after every object is durable. Resume accepts a matching sealed generation or explicitly restores/forks that generation; never mixes mutable rows with stale exports. Pin store/schema/canonicalization/authority modes per run; rollback routes new runs only, preserving existing artifacts.
**Acceptance:** Kill before/after row commit, export completion and manifest publication; duplicate attempts, stale writers and concurrent exports cannot create mixed generations. Reject tampered files/symlinks and incompatible schema versions. A replay manifest binds input snapshot, actor/path/step/attempt identity, validated output, repair order, code/policy versions and RNG identity; `step_id/call_n` alone is insufficient across paths/retries.
**Owner:** B1/controller owner; decide before implementation. Reuse ADR 0001:44–63 and ADR 0002:58–62 rather than introducing a second advancement authority.

### D5 — P1: the probability-authoring principle contradicts the default estimator
**Conflict:** P:20 forbids LLM probability intuition, but R-10/E-01/E-06 request probability distributions (P:121,209,214), and E-07 gives the research posterior weight 1.0 (P:217). R-10 also writes a first-party forecast during “research,” while II.1 restricts forecast writers to estimation. Applying a 0.03 floor even at weight 1.0 breaks G1's byte-identical default for probabilities near zero/one.
**Amend:** Separate the preserved legacy authority from the proposed computed mode. Recommend retaining legacy probabilities unchanged while the computed mode is shadow: LLMs propose evidence/parameter/model inputs; a named deterministic estimator derives distributions. If subjective LLM probability lanes are retained, declare that explicit exception instead of claiming the strict principle. Classify R-10 assessments as first-party `forecast` regardless of phase; R-13 must not relabel them `inferred`. Use an explicit identity aggregation path with no floor/normalization/extremization when only legacy authority is active (existing `forecast_aggregator.py:147–149`).
**Acceptance:** Extreme-probability fixtures remain byte-identical in identity mode. No unit gate, rollout flag or new lane name promotes a changed probability policy; freeze the candidate and require I-21's prospective lane-specific gate. Explain denominator/dependence handling for the proposed n≥30 rule before promotion, not as a B1 prerequisite.
**Owner:** Estimation owner plus owner approval; block C7/G1 probability contract acceptance, not the bounded B1 shadow-store work.

### D6 — P1: shared context and lookahead can bypass I-1/I-33
**Conflict:** P:291 requires CONTRACT/SNAPSHOT caching across a run/phase, but S-00/S-05 permit only clock context, while research/estimation contracts contain predicates/probabilities. S-04 freezes other actors on their plans (P:180), which can expose private plans indirectly through option scores. An “assumed” relabel of posterior-derived parameters would bypass a class-only filter.
**Amend:** Make context projections and cache keys capability-specific. Actor context excludes first-party assessments, estimators, aggregation, scenario classifiers and their probability-derived content. Keep outcome predicates in the scorer. Permit structural assumptions with explicit independent bases; I-33 concerns first-party estimator output, not every numeric uncertainty prior. Lookahead uses only the actor's visible beliefs/public commitments, never rival private plans, hidden path draws or unreleased truth; insufficient visible inputs yield unavailable options. Reuse current `forecast_case.py:665` and `target_actors.py:255`, not an analyst-wide query.
**Acceptance:** Perturb only estimator probabilities/classifiers or rival-private state while holding visible evidence, structure and RNG fixed: actor payloads, option tables and raw trajectories remain identical. Test laundering through assumed rows, summaries, cruxes and caches. Cross-path decision reuse is allowed only for identical complete authorized decision inputs and frozen policy/model context.
**Owner:** B1 query/context owner plus simulation owner; scope/cache rules block B1, lookahead specifics block F4.

### D7 — P1: card conditionals and critic feedback violate the stated publication fence
**Conflict:** V-01/Part VI put simulation conditionals on the card (P:225,278), while V-05/V-07/G4 permit simulated content only in the record view (P:230,236,348). E-08 consumes simulation signposts and V-06 checks the whole card, creating an indirect simulation→crux/critic→narrative path even at zero weight. An executive brief rendered from that card inherits the same ambiguity.
**Amend:** Add an explicit ADR 0003 amendment defining one deterministic simulated card subview/bridge, with banner, input hash, coverage/assumptions and zero probability authority. Keep ordinary evidence/narrative/critic/repair inputs simulation-free; partition empirical versus simulated cruxes/signposts. Public views receive redacted display projections, not `analyst` access to private rationales. A token resolving to a row must also resolve to a permitted class/scope/unit/version; I-31 alone does not prevent class laundering.
**Acceptance:** Extend RW-11 by varying only simulation records: forecast numbers and every narrative/critic/repair prompt remain byte-identical; only explicitly fenced diagnostic subviews/hashes may differ. Missing/invalid/hollow records remain stubs or absent; `no_update` still omits diagnostics. Do not fix V-07 by silently removing the banner or widening all writer access.
**Owner:** Publication owner and owner ADR approval; block G4/changed publication, not B1 schema prototyping.

### D8 — P1: unresolved effects occur after target evaluation with no commit rule
**Conflict:** S-07/IV.3 evaluate target/predicates and emit events before S-08 estimates missing effects (P:188–196,256–257). The plan does not say whether those effects change the already-scored period, enter a later queue, or get counted alongside a bound mechanism; S-10 also overlaps settlement inside S-07.
**Amend:** Define one staged period transaction: freeze observations; collect/validate actions and dated shocks; obtain unresolved effect proposals against a named pre-effect snapshot; validate and enqueue once; apply effects due at this boundary; propagate/conserve; then evaluate predicates, settle outcomes and emit one committed event batch. Specify absolute versus relative onset, duration, zero-lag visibility, same-target conflict/tie order, exactly-once effect IDs and derived-variable write rejection. Bound-mechanism actions MUST NOT also receive fallback effects. Define a fallback when the prior has no mode; do not invent an implicit zero.
**Acceptance:** Two simultaneous writes, delayed onset, shock+action on one target, duplicate replay and same-period breach produce identical causal outcomes under reordered worker completion and crash/restart. Actor B never observes actor A's same-period uncommitted action. Persist S-08 draws/outputs so replay makes no model call. Reuse current simultaneous-observation and lag seams (`target_simulation.py:236–266,408–423`); do not claim the existing engine already implements this new order.
**Owner:** Simulation/kernel owner; resolve before F1/F6 engine contracts, with required identity fields fixed in B1.
