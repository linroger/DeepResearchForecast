# World Anchor implementation plan

**Date:** 2026-10-29
**Status:** Approved for code and offline acceptance on2026-10-29. No provider spending, deployment or scheduler authorization.
**Scope:** One optional, evidence-bound World Anchor producer and its actual reflexive-world consumers. This does not approve the full overhaul, a new workflow controller/database, provider spend, scheduler activation, or changed forecast probability authority.

## 1. Intended result

The finished research supplies an inventory of retained quantitative, qualitative and temporal claims. A demand-driven binder matches explicit world requirements to those claims. Deterministic admission produces one immutable `world-anchor/v1` pack, a readable anchor sheet and a gap file. The seed and supported mechanism runtime consume an admitted projection of that pack; actor prompts receive only their authorized subset. Every requirement is bound, conflicted, assumed under an allowed policy, or explicitly open.

“All figures” means a traceable inventory of the retained research corpus, including rejected and unselected candidates with reasons. It does not mean putting every number in the simulator or claiming exhaustive extraction from unavailable pages. The human report can identify candidate omissions, but neither its narrative nor a new model's interpretation authenticates a claim.

Success requires a meaningful change at a real downstream consumer, not merely a valid JSON file: a source-supported baseline/lever reaches initial state, a typed event reaches its due period, an admitted action changes an input and propagates through a named mechanism, and derived target output appears in the diagnostic record with provenance.

## 3. Contract changes before coding

### 3.1 Requirement and evidence identity

Use a deterministic requirement registry with `requirement_id`, kind, stable entity/metric identity, required unit, reference period, accepted evidence classes, priority and consumer. Derive it from the admitted forecast contract and selected mechanism templates. Scenario labels or free-text driver names can nominate candidates but cannot create a settlement definition. If the old specimen lacks a usable typed target/identity, produce `missing_contract` or a reviewed explicit fixture contract; do not infer it from the largest numeric row.

Before ontology/cast sealing, actor references use the research registry and explicit alias evidence. Bind them to final entity UUIDs through a separate validated join receipt after ontology. Reject ambiguous aliases and one-dossier/multiple-UUID collisions. Do not synthesize arbitrary actor UUIDs or mutate an already sealed anchor to complete the join.

Each evidence reference binds run/snapshot identity, KIQ plus local fact index or stable claim ID, source ID, source-content hash, retained passage location and exact quote. Source IDs such as S107 are local to one research track and snapshot. Persist a crosswalk between track-owned ledger SIDs, report citation positions, URL-derived source IDs, target sourceIds and official dataset references; do not join them by display label. Dispatch input adapters by admitted authority/schema because target-first quantitative.json contains case nodes while legacy quantitative.json contains extracted rows. Number occurrence is necessary, not sufficient: admission checks entity, metric, denominator, reference period, geography, unit, value kind and any declared conversion. Conflicts and superseded same-period vintages remain explicit; different periods are not automatically conflicts.

### 3.2 Time and epistemic status

Separate `reference_period`, `effective_at`, `published_at`, `available_at`, `retrieved_at`, `vintage` and simulated `visible_at`. A historical-looking date does not admit data published after the research cutoff. Source availability must be supported or unknown; retrieval time alone does not establish historical availability.

Maintain independent fields for epistemic class (`observed`, `reported`, `third_party_forecast`, `analyst_inferred`, `assumed`, `simulated`) and binding status (`bound`, `conflict`, `gap`, `contested`). A future scheduled event announced before cutoff can be known now while applying later. A future observation value is not known merely because its release date can be predicted. Preserve historical precedents outside the future event queue.

Cadence/lag may be catalogued, source-stated, inferred with basis/uncertainty, or unknown. Do not invent monthly cadence from one publication or impose a precise next release from irregular sources. Observation admission must consume these fields; storing them alone is insufficient. New simulated observations remain simulated and cannot enter the observed evidence ledger.

### 3.3 Actor knowledge and authority

Every dossier item carries claim references, epistemic class, subject/owner, visibility and availability. `actor_known` is an admission decision based on supported self-statements, mandates or permissible public knowledge, not a label the binding LLM can grant itself. When anchor-v1 is enabled, analyst-authored inference about the actor is absent from the **entire actual actor request**, including labeled research evidence in either system or user messages. Replace or filter existing role-dossier, config behavior, shared/private brief, cached-summary and lookahead channels; appending a clean anchor projection beside the old inference-bearing dossier is insufficient. Other actors' private beliefs/plans and all first-party estimator/scenario probabilities remain excluded.

Source-backed red lines must compile to the supported typed predicate grammar or remain non-executable narrative/gaps. Levers require sole/shared/consent/vote authority and named co-holders where applicable. An intention is not an accomplished action or guaranteed scheduled event. Canonical agency declarations use the existing C5 validator and final ontology basis; conflicting upper-type suggestions remain conflicts.

### 3.4 Mechanisms and failure behavior

The pack includes an explicit `mechanisms[]` section missing from the proposed emission example: IDs, supported template/version, input/output node IDs, typed parameter values/ranges/units/bases, effects, lags and applicability. Reuse the current closed mechanism grammar and dimensional/identity admission. No arbitrary expression evaluation or model-invented code.

Identity residuals use declared scale/unit tolerances. Contested required inputs make dependent derived nodes unavailable or non-ready; never average disagreements or set a missing target/elasticity to zero. Allowed library priors retain their version and rationale as assumptions. Missing identity/settlement/required authority has no generic prior fallback.

A well-formed pack containing gaps is valid evidence output. Its `readiness` determines whether simulation preparation can proceed. Tampered, cross-run, invalid or missing required packs fail closed when the feature is enabled. Only the off/legacy mode bypasses anchoring. “Never empty” means a meaningful coverage/gap result, not fabricated anchors.

## 4. Producer and execution flow

W0. **Requirements and coverage:** Build the registry from the admitted contract/templates/research actor registry. Inventory all retained typed claims and mark truncation, unsupported shapes and missing pages explicitly.

W1. **Candidate retrieval:** Match stable entity/metric/unit/period and rank deterministically. Initial delivery uses local lexical/entity matching and explicit aliases. Any embedding ranking is an optional later adapter over frozen local/cached vectors with model/version/tie-break pins; it cannot add hidden provider calls. Keep at most six candidates per requirement and retain the selection receipt. Prose-only rows can identify a gap but cannot pass factual admission.

W2. **Binding proposal:** Use the existing model transport, not a new agent framework. Group by requirement kind; at most twelve requirements per request, reduced to fit actual input/output budgets. Provide the requested CORE/CONTRACT/REQUIREMENTS/CANDIDATES layout. Treat candidate content as quoted data. Replies propose matches, conflicts or gaps; deterministic code retains authority. Pin model/profile/prompt/schema versions. Temperature0.1 only where supported by the selected provider. Never truncate a structured reply and call it valid.

W3. **Admission:** Verify source membership, passage/hash/span, number/unit/entity/period, cutoff/availability, actor visibility, authority references, event classification and identity consistency. One bounded repair, if used, consumes the same total attempt and token budgets. Bad source IDs or fabricated claims remain failures/gaps, never trusted corrections.

W4. **Bounded gap resolution:** First consult already captured official data. Execute any permitted new collection/follow-up while the producer still owns an open gathering generation, before its official-data admission closes and before assessment/report/case seals. If actual retrieval is separately allowed, use a registered matching catalog series, no arbitrary URL/model-selected method; record no-match and denied-access outcomes. One follow-up round covers only the verbatim gap requirements. Re-enter that open generation's source ledger and admission path. A gap discovered after sealing stays open in that generation; resolving it requires an explicitly versioned new research generation that preserves its predecessor and retained budget. No live follow-up is performed by a replay reader. A supported library assumption may resolve an eligible model parameter; otherwise leave it open. Budget, authorization, cancellation and unknown-outcome stops propagate, never degrade into extra calls.

W5. **Temporal projection:** Attach supported cadence/lag/history with explicit uncertainty. Separate same-period forecast revisions from observation history. Compile announcement visibility separately from event effects and observation releases.

W6. **Emission and sealing:** Produce `world_anchor.json`, `world_anchor.md`, `world_anchor_gaps.json`, and a compact coverage receipt. The JSON is authority; other outputs render it deterministically. Seal the pack and final research generation together through a manifest. The later UUID join receipt is sealed with cast/config preparation and references that immutable research manifest; it is not required before ontology exists. The manifest binds both final case hash and anchor hash; `contract_hash` binds the pre-binding contract, avoiding a circular case/anchor hash definition. Publish the manifest last after all referenced artifacts are durable.

The user-visible stage is World Anchor, after evidence gathering/finalize material and before ontology/PREPARE. Requirements may be derived earlier from the admitted plan contract; late evidence discovery must finish before gathering admission closes. Research-only runs with the mode enabled emit the anchor pack/coverage too, before their existing early return; they do not create ontology or simulation. It is implemented first as a research-completion substage under the existing controller. For target-first research, binding must happen **before assessment/estimator computation and final case sealing**, so accepted bindings are compiled into the same case. For the legacy research route, invoke the common producer before research receipt closure/ontology, and regenerate affected projections before sealing if an allowed gap pass changed evidence. A single hook in phase_finalize is insufficient because target-first bypasses it. Do not rewrite a frozen case after the parent has admitted it.

## 5. Emitted pack and consumer ownership

The closed, versioned schema contains: schema/run/generation/policy identity; contract and input snapshot hashes; cutoff/horizon; requirement registry and coverage; variables with typed value kind, periods, vintage, availability, cadence, conflicts and history; identities; mechanisms; actor dossiers; calendar; hazards/effects; indicators; reference classes; gaps and resolution attempts; readiness; and metering provenance. References point to retained evidence; public and actor projections do not expose the raw private pack.

Consumer delivery covers three distinct selected engine paths: `oasis-legacy` reflexive coordinator, `world-v1` compiled world, and `target-first-v1`. Do not switch an existing run's engine to make anchoring work. Consumer delivery is explicit:

1. **Research/case producer:** Anchors populate admitted node values and mechanism parameters before sealing. Preserve `forecast_case` as numeric authority and current estimator policy.
2. **Ontology/cast/config:** Actor join receipt resolves UUIDs once; existing agency-class mapping consumes only validated declarations before cast-manifest sealing. Omitted map retains current serialization.
3. **Legacy seed and runtime:** An optional validated pack argument supplies target-first ordered state, typed plan/red-line/calendar/hazard projections and gaps. A versioned projection retains value kind and temporal fields the current runtime understands. Wire explicit load/save fields in `WorldModel.from_seed`, variable serialization and resume state. Route events through `_build_scheduled_events` and actual due effects. Bind indicators to a named observation/trigger/signpost consumer; existing `scenario_indicators` are not loaded by the runtime. New fields with no runtime consumer remain unavailable, not silently inert. Required target/mechanism changes must be exercised through actual propagation; no claim that adding a target label gives the legacy arbiter a numerical compiler.
4. **Compiled world-v1:** Thread the validated optional pack through `PipelineOrchestrator._run_world_stages` → `SimulationManager.prepare_world_simulation` → `WorldSimulationService.prepare_model` → `compile_world_spec`. Project supported state into existing initialState/accounts/metrics/rules/relations, and supported behavior into actionCatalog/scheduledEvents/flows. Add explicit anchor-evidence provenance admission with exact pack/requirement/observation references and typed field/target mapping; do not forge actor source_claim entries or use report excerpts to authenticate quantities. Compiler-owned sourceBindings and world_input_manifest bind the anchor generation/hash, immutable target contract and all admitted parameter references. Raw candidate/modeler output cannot author those bindings. Reuse/fork checks revalidate them. Preserve existing compiler gap/authority rules; unsupported mechanisms block enabled preparation with typed modeling gaps. This adapter does not replace the kernel.
5. **Target runtime:** Consume the final admitted case and a scoped observation projection; variable IDs, action levers, mechanism inputs and output target must join exactly. Read-only derived values reject actor/arbiter writes.
6. **Actor briefs:** Construct authorized dossier projections before shared or per-actor summaries; test self-inference, rival privacy, time, estimator leakage and cache isolation end to end.
7. **Records/reports:** Add anchor provenance, assumptions/gaps and supported initial/final variable comparisons through the explicit `simulation_record._Artifacts` and `_setup_reflexive` projections; arbitrary world-model metadata is currently dropped. Preserve ADR0003/RW-11: simulation-derived content does not author forecast numbers or enter unrestricted narrative/critic prompts. New report-facing views use a redacted projection.

## 6. Feature and budget contract

`SIM_WORLD_ANCHOR` can select the default for **new runs only**. Write explicit mode=`v1`, policy version and expected generation/hash **only for enabled runs**. Absence permanently means off, including newly created off runs. Reuse/retry/fork consumers interpret the saved pin or absence without consulting the environment. Strict I-30 covers the complete enabled actor payload across all existing and new channels; off mode retains the existing labeled-inference contract so saved payloads do not silently change. Present-but-invalid enabled artifacts cannot fall back to legacy extraction. Off mode adds no fields or calls and preserves existing serialization, prompts, RNG consumption, variable ordering and receipt identities under the current fixed-timestamp fixture convention.

Use a hard maximum of20 physical model attempts and150,000 total input/output tokens for the anchor stage, including repairs and follow-up calls. These are ceilings, not a minimum8 calls. Count any model-based embedding calls if later added. Tool calls have a separate small closed allowance (initial proposal: at most one logical catalog lookup per admitted gap and at most eight physical catalog attempts across the stage, including retries). All costs also draw from the durable whole-run authorization without refunds, renewal or epoch resets.

Stage ceilings require new durable admission fields; current whole-run currency metering does not enforce them. The reviewed request/manifest version must issue one stable `anchor_budget_scope_id`, inherited by all registered descendants, repair/follow-up calls and restart attempts. Do not derive membership from a current nested stage name or a participant PID. Extend the existing ledger transaction to atomically reserve (a) the whole-run monetary maximum, (b) one physical model/tool attempt in its corresponding stage counter, and (c) the enforceable input-plus-output token envelope for model calls before the raw send. Retain every committed envelope, including failed or unknown outcomes; usage never refunds stage capacity. Missing/unverifiable usage halts under the existing outcome contract. Concurrent final-slot claims can admit at most one sender. A new research revision within the same authorization inherits prior anchor reservations; replay makes no reservation or call.

A token envelope must cover the final serialized provider request and inclusive output/reasoning cap, using a qualified enforceable input bound. If only the full context-window ceiling is supported, reserve that ceiling; do not substitute optimistic character/token estimates. If one qualified request exceeds the150k stage allowance, refuse the profile with a typed budget/qualification gap. The plan does not promise8–20 usable calls for every model. A smaller verified input profile must be qualified before a denser live batching claim. The spending owner/reviewer must freeze this atomic multi-limit contract before binder execution tests; no second quota store is introduced.

The supplied worst-case batch size (12 requirements ×6 candidates ×400 tokens) is28,800 candidate tokens before other context;20 such calls cannot satisfy150k. Packing must reserve output/retry capacity and stop with typed budget gaps when the remaining budget cannot admit another batch. Two thousand output tokens is a provider request ceiling; batch size must shrink to preserve complete structured output.

The current spending profile binds exactly seven request fields and target-first execution. Anchor mode, limits and source policy must be included in a reviewed versioned request/manifest contract before paid use. Do not mutate frozen v1 authorizations or silently broaden the launcher to legacy runs. First implementation uses fake transports and captured official data; live qualification for either non-target-first engine is a separate profile decision. No real tariff, account limit or dollar budget is approved here.

The five-minute offline wall target applies to a named frozen scripted replay on the provisioned machine; measure and report it. It does not promise live LLM/network latency. Resume reuses a complete matching pack without model/tool calls; incomplete producer recovery follows an explicit checkpoint contract or restarts only within the same retained limits when that path is reviewed. No invented target-v3 checkpoint compatibility.

## 7. Incremental implementation and disjoint owners

0. **Coordinator prerequisites:** Close the existing spending integration/delivery gate; inventory/hash-copy the relevant saved pages and KIQ/official artifacts into a new private snapshot. Establish the exact target/baseline contract and evidence-supported specimen expectations. Freeze the anchor schema, consumer matrix and budget request version.
1. **Contract/retrieval owner:** Add a pure bridge module for requirements, evidence indexing, deterministic retrieval, schema/admission, gaps and serialization. Candidate paths: `deerflow_bridge/world_anchor.py` and dedicated unit/adversarial tests. No application imports or ambient filesystem/network work at import time.
2. **Binding/research owner:** Add one bounded prompt/transport adapter and integrate both research finalize paths before seals. Reuse current numeric/source validators and metering. Own the corresponding bridge integration tests and source-copy/deployment parity updates in agreement with the coordinator.
3. **Seed/cast/actor owner:** Wire the validated optional pack through preparation, UUID join, existing C5 map, seed, decision visibility and actual runtime projections. Own focused consumer tests; no changes to probability-authoring policy. The compiled world-v1 adapter has a separate owner for `world_simulation/{compiler,service,contracts,artifacts,observations}` and its focused tests; coordinator owns the manager/orchestrator call-through to avoid overlapping edits.
4. **Lifecycle/report coordinator:** Pin modes/hashes, completion receipts, reuse/fork invalidation and diagnostic provenance. Own lifecycle and public-consumer tests, compatibility gate and shared docs. Avoid overlapping producer/consumer files by freezing exact ownership before edits.
5. **Independent reviewer:** Read-only producer-to-consumer and temporal/authority audit; review exact frozen source and private receipts. Close reproduced findings with focused red/green evidence before the final composed gate.

Each slice must have a concrete consumer or explicit dependency; none is accepted solely on helper coverage. This is one feature delivered in steps, not the whole overhaul. No calendar estimate is accepted until the source/fixture gaps are resolved.
