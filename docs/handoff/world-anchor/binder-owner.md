## Current interfaces and implementation

`linear_research.run(..., world_anchor_control=None)` validates the loaded in-memory question and actual CLI arguments against the bound seven- or eight-field request before bridge/model construction. An enabled v2 call with omitted Python control uses `world_anchor_binding.production_control(binding, request)`. That factory reads only fixed `binding.root/control/request.json` and `control/anchor_budget.json`, validates the full request/core profile, and requires both source-policy pins to equal `source_policy_hash()`. No environment selector or argv rewrite is used.

`source_policy_template()` is the versioned built-in policy; `source_policy_hash()` is stdlib-only and safe for private preparation. `PendingProducerControl` pins the immutable request, budget/profile, base policy hash and generation. The engine reuse identity pins that base policy. At the anchor phase, `materialize_control(engine, pending, case=...)` builds the explicit native contract/policy from the admitted case and `target/world_anchor_identities.json`, authenticated by `targetResearch.anchorIdentityHash` using `world_anchor.anchor_hash`. `TARGET_IDENTITIES_INSTRUCTIONS` describes the planning response's additive `worldAnchorIdentities={nodes,parameters}` declaration. Settlement is never inferred from an incidental numeric row. An explicit fixture `ProducerControl` remains supported by `producer_control(...)` and is tested separately.

The shared production entry is `run_anchor_stage(engine, control, *, case=None)`. Linear calls it after gather/gap and before context sealing/synthesis; target calls it after gathering and before native compilation/assessment. Enabled gathering closure uses the anchor collection marker, so ordinary gather completion does not prematurely freeze W4 on resume. Pauli's `apply_anchors_to_case` and `validate_anchored_case` are used before assessment and final case persistence. The producer does not duplicate native compilation or promote controller lifecycle to ready.

`ScopedGatewayCallbacks` uses the existing qualified ModelGateway's concrete SDK client and wire/retry validators. Each callback issues one `client.with_raw_response.create` through core dispatch and `capture_dispatch_receipts`, fingerprints full provider JSON before parsing, and links request/response/attempt identities. Extraction and independent semantic review are distinct calls; extractor rationale/self-approval is excluded from review. One bounded JSON repair is a separately retained physical attempt. Unknown outcomes propagate, preserve entry-only handoff and prevent publication. Full qualified input ceiling and inclusive output cap are reserved on each physical attempt.

`PinnedInput` and `snapshot_research_inputs(engine, control, *, case=None, previous=None)` preserve original ledger/KIQ/page/data/case bytes plus explicit SID/source joins. A successor requires the previous `ResearchInputs` and opaque index, reopens their hash-checked artifacts, preserves scope/requirements/policy, and retains a predecessor receipt with the prior manifest and artifact hashes. It never accepts an arbitrary parent hash. Changed input invalidates earlier proposal/review bindings; rebuilds remain inside the same retained budget scope. Publication occurs after collection closes.

`RegisteredCatalogAdapter` is a fixed qualified recipe: exact identity, catalog route/hash, payload, credential mapping and normalized-series pointers. No model-selected URL or fallback is used. W4 records registered gap identities, uses actual HTTP dispatch (fake transport only in acceptance), admits the returned series through existing tools, and creates a successor snapshot. No-match and unsupported results remain gaps. Dedicated positive/failure W4 acceptance is still being completed.

Publication uses `world_anchor_publication.publish_completion` and immediately reloads the result. Scope handoff is fixed `handoff/world_anchor_scope_handoff.json`, exactly `{schema_version:'world-anchor-scope-handoff/v1', receipts:[enter,exit], completion:<exact finish object>}`. Immediately after entry it contains `[enter]` and `completion:null`. Completion's `result:'sealed'` describes structural publication; all per-engine readiness rows and gaps remain in the pack. Parent adoption occurs only after child join and authenticates the completion hash against the exit transition before admitting the artifact manifest. The lifecycle remains pending until parent outer-seal validation.
