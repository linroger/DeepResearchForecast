## Decision for the parent plan

Prefer **independent native adapters** behind DRF's existing owners. News discovery adds useful coverage; Polymarket retrieval already exists in three places. An optional Oddsense CLI wrapper would still require all the DRF contracts below, plus subprocess lifecycle/version/error handling; it does not solve citation, cutoff or replay integration. Current researcher instructions explicitly permit the market tool/public `web_fetch` and forbid researcher shell/CLI use ([market skill:28–41](/Users/rogerlin/Downloads/DeepResearchForecast/deerflow_bridge/skills/prediction-markets/SKILL.md:28)). A trusted-parent wrapper is a separate possible design, not an existing permitted agent tool.

Keep NewsAPI discovery narrow and optional; treat Reddit as a separately enabled lead source pending authentication/access and evidence-retention decisions. Defer Kalshi until exchange-aware identity and consumer handling are agreed. Do not adopt lexicon tone as event probability, `(tone+1)/2` divergence, or fuzzy-title arbitrage. These exclusions follow the parent's upstream findings; no vendor code copying is proposed.
