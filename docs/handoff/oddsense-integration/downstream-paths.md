## 2. Provenance, time, equivalence and reuse boundaries

1. **Generic shape does not imply generic execution.** Rows carry `exchange`, but merge keys, forecast lookup, anchors, comparison and monitor use bare IDs. Merge fixes container `source="polymarket"`; market rendering/pack/critique call the data Polymarket. `requote_markets` sends every accepted ID to Gamma regardless of `exchange`. Adding Kalshi rows to `markets[]` would expose them to that route and to probability revision. Keep `PolymarketClient` a concrete provider client; extend the current ownership boundary with an explicit contextual lane, not a second forecasting system. [Refresh:339–388](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/utils/prediction_markets.py:339); [provider labels:580–626](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/utils/prediction_markets.py:580).
2. **`as_of` currently describes a container, not every quote.** Merge chooses the lexicographically greatest container timestamp and attaches per-track timestamps; it does not parse/normalize timezone offsets or create immutable per-row capture identities. Normalized backend rows do not define a capture ID, provider-observed timestamp, response hash or market-rule hash. Report/simulation loaders discard the container timestamp/status. Preserve source-observed, fetched and cutoff times separately for added context; absence must remain explicit.
3. **Research price is not consistently preserved downstream.** Client refresh preserves the original `price_at_research` idempotently and marks failed rows, but `_build_market_anchor` sets **both** anchor prices from current `implied_yes_prob`, ignoring an existing original research price. Thus a 34% research row refreshed to 41% can yield an anchor labeled research=41%; tooltip, comparison and monitor inherit it. This is a source-observed gap, not an executed reproduction. [Client:369–384](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/utils/prediction_markets.py:369); [anchor:3444–3449](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/forecast_extractor.py:3444).
4. **Freshness is weaker than a replay cutoff.** Report defaults enable markets and refresh. A partially failed batch is globally non-stale if any row refreshes; row failures are not displayed by the shared renderer. An explicit empty research result still triggers live report recovery. Reusing the research stage therefore does not freeze report market evidence. Historical-cutoff work needs an explicit no-refetch rule plus persisted report capture, rather than interpreting the existing refresh switch as capture equivalence. [Defaults:1441–1476](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/config.py:1441).
5. **Relevance, contract equivalence and probability influence are separate gates.** Semantic matching requests same event/compatible timeframe but feeds truncated statements/questions/end dates, not full provider settlement rules. The integrity gate requires URL/end date/exact-or-near/confidence ≥0.5 and either known proposition compatibility or a byte-bound semantic match; influence defaults to ≥0.6. These are existing controls, not proof of cross-venue equivalence. Any future anchoring also needs matching event, YES orientation, threshold/units, date/timezone, source and settlement rules; fuzzy discovery remains contextual.
6. **Research generation ownership already exists.** `prediction_markets.json` is in `_RESEARCH_CONTRACT_FILES`; generation promotion copies/fingerprints it and removes stale optional artifacts. Stage artifact registration also lists market candidate JSONL; optional/legacy stage manifests permit missing entries, while recorded paths/hashes/bytes/schema are checked on reuse. Candidate JSONL is not in that fixed generation-file tuple. Neither `market_price_history.json` nor a new contextual filename is in the inspected fixed tuple/specs; new durable context needs deliberate generation, promotion and reuse coverage. [Tuple:3209–3218](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:3209); [fingerprints:3755–3782](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:3755); [promotion:3970–4027](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:3970); [stage specs:10021–10043](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:10021); [reuse:10365–10445](/Users/rogerlin/Downloads/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:10365).
7. **Status is not yet end-to-end faithful.** Merge distinguishes transport failure, timeout, irrelevant candidates and selected rows, yet all-timeout output can pair `state="inflight_timeout"` with `empty_reason="no_equivalent_market"`; the current test explicitly pins that pair. Dossier empty presentation special-cases only `empty_reason="transport_failure"`. Report fallback loses the original reason entirely. A contextual feed must retain unavailable/disabled/not-attempted/verified-empty distinctions. [Pinned test:309–322](/Users/rogerlin/Downloads/DeepResearchForecast/backend/tests/test_parallel_research_merge.py:309).
8. **Simulation and UI have distinct limits.** Legacy market prompts omit IDs, venue, capture time and rule identity; persona lookup by graph may pick a different pipeline when graphs are reused. Canonical actor public-context admission must remain authoritative. Dossier accepts only an object container although backend loaders accept bare lists; cards format all volume as USD and do not show venue. Dashboard tiles expose neither capture time nor influence history; the binary table/Markdown carry more detail. Context-only feeds require their own clearly labeled rendering and cannot be made safe merely by renaming a heading.

## 3. Minimal safe integration recommendation for the parent's plan

- Preserve existing Polymarket anchoring/re-quote/resolution behavior and owners. Add a bounded, versioned **context carrier** under the existing market/research integration boundary for Kalshi discovery and news/Reddit evidence. Its exact filename/API belongs in the parent's approved contract; do not insert these rows into anchor-eligible `prediction_markets.markets[]` in the initial slice.
- Carry provider + native ID + evidence kind, canonical URL, title/rules reference, fetched time, provider-observed/publication time when available, research cutoff, units/currency, raw-response digest/reference and explicit retrieval status. Keep normalized dollar price, bid, ask, last trade and derived midpoint distinguished. Mark context as ineligible for forecast anchoring/revision/resolution. News/community statements remain attributed evidence, with no sentiment-to-probability conversion.
- Route that carrier through existing research generation promotion/reuse and report-local evidence binding. Expose context with citations in dossier/report prose and its Markdown export; PDF follows audited prose/chart dependencies. Show source/time/status in UI. Do not call a frontend-only tile an export integration or a report fallback a research capture.
- Keep simulation admission separately gated: source-bound public information only, available by the actor/research cutoff. No raw community feed, modeler-only evidence or unbound quote enters canonical common knowledge. Adding discovery data does not authorize expanding actor access.
- Defer cross-platform forecast anchors, automatic Kalshi settlement, trading/arbitrage and historical-price charts. A later approved slice may introduce provider-qualified identities and dispatch while preserving the same forecast/market contract; verified settlement equivalence is a prerequisite, not an output inferred from similar titles.
