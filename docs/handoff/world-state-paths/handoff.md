## 6) Findings, Decisions, Assumptions
- **D1 (what counts as a documented shock):** a risk row needs an event, a probability (a number strictly between 0 and 1, a percentage, or a count such as "1 in 20" / "2 of 10"), the window that probability refers to (day … year, or the forecast horizon, stated in a field or in the probability text) and a source. Missing any of them → a typed gap, no shock. The conversion to a period probability assumes a constant hazard over the window (p_period = 1 − (1 − p)^(days/window_days)); that is a modelling assumption, recorded here and in the design, not an invented number.
- **D2 (where the agents live):** path 0 is computed exactly as before (same RNG, same arbiter temperature 0.3) and is the only path rendered into briefs, so K>1 changes no agent-facing text. The other paths are counterfactual siblings conditional on the actors' realised decisions: they capture world-side uncertainty (rolls, arbiter resolution), not the actors' reaction to a divergent world. Recorded as a limitation.
- **D3 (arbiter per path):** every path runs its own arbiter call on its own world (so a shock that fired only there is resolved there), concurrently with path 0. Paths 1..K−1 sample at `SIM_WORLD_PATH_TEMPERATURE` (default 0.7, clamped to [0, 1]); setting it to 0.3 turns the extra sampling off. A path whose arbiter fails commits deterministically, like path 0.
- **D4 (cap):** K ≤ 8 (`MAX_WORLD_PATHS`): K arbiter calls per round, no extra decisions.
- **D5 (byte identity):** every new key is written only when it has content — `shocks` in the world dict, `shocks_fired` in the round record and history row, `shocks_enabled` in the world settings (only when the world has shocks), `paths` in trajectory rows and the summary and `world_paths.json` (only with K>1) — and the shocks draw from the round RNG only after the due effects. A world without shocks and K=1 therefore writes exactly the bytes it wrote before (§7).
- **D6 (shock clamp base):** several shocks that hit one fact in the same period are bounded together against the fact's value before this period's shocks, so two +30% shocks cannot compound past one clamp; a shock never flips a fact's sign (as announced settings).
- **D7 (sibling start and resume):** the siblings start as copies of path 0 (round trip through `to_dict` / `from_dict`, the same form a resume reads). A resume restores them from `world_paths.json` only when its `committed_round` equals the world's; otherwise they restart from path 0 and `restarted_at_round` records it rather than pretending continuity.
- **D8 (temperature default 0.7):** with K>1 the owner has opted into the cost; at 0.3 the siblings would often repeat path 0 call for call unless a shock or a probabilistic effect separated them. 0.7 is a moderate sample, bounded at 1.0; `SIM_WORLD_PATH_TEMPERATURE=0.3` turns the extra sampling off.
- **D9 (no research-engine change):** the v3 extraction prompts are not taught to emit `risks` here; that changes paid research runs and needs its own live check (§9). Until then every live run records `no_documented_shocks`.
- **Finding F5 (cost, measured):** arbiter prompts rebuilt with this code from the saved worlds of `sim_d6ebcc77e22d` and `sim_1838cf014c0b` average 2,393 and 2,656 cl100k tokens (max 2,996); output is capped at 2,200. One extra path costs at most ≈ 5.2k tokens per round; K=4 over 9 rounds ≈ 27 calls, 65–81k prompt + ≤ 59k completion tokens vs ≈ 1.29 M tokens for that simulation. Evidence: `before-after` dir below, `arbiter_cost.py` / `arbiter_cost_output.txt`.
- **Finding F6 (self-review, fixed):** a structured `delta: "-5%"` on a fact that is not itself a percentage was read as −5 units (`parse_quantity` keeps the number and reports the `%` as its unit). A percent-valued `delta` / `new_value` of such a fact now gives no size (direction only, or dropped without one); pinned by `test_effect_sizes_are_documented_or_left_to_the_arbiter` (15 cases).
- **Assumption A1 (open):** a sibling arbiter at 0.7 produces valid JSON as often as at 0.3. Falsified only by a live run; a sibling's invalid or failed arbiter only freezes that sibling's world channel for the round (counted in `per_path[].arbiter_failed_rounds`).
