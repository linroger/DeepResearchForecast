## 1. Immediate decision: can the existing clients review rendered pages?

**Conditional yes for an existing image-capable HTTP endpoint/model; no supported image transport through the current generic CLI adapters. No new provider is intrinsically required, but not every currently declared model can perform the review.**

**Chat Completions versus Responses:** the inspected `LLMClient` preserves supplied `image_url` content parts on its OpenAI-compatible Chat Completions route because it forwards `messages` unchanged (`llm_client.py:1029–1048`) into `client.chat.completions.create` (`llm_client.py:987–1006`). The native-tool route likewise forwards messages (`llm_client.py:762–769`). There is no Responses API implementation in this inspected client: no conversion of chat `image_url` parts into a Responses input, nor a `responses.create` branch. Responses image handling elsewhere is therefore unverified and must not be claimed from this audit. The transport conclusion does not establish model comprehension or successful endpoint acceptance.

## 3. Smallest real bounded agent flow

Use one export agent inside the parent's persisted export job, with deterministic local tools and a separate review pass. It need not be a custom-agent platform or a new research pipeline. There must be observable model decisions based on the skill, tool observations and actual artifacts; a renderer invocation plus an “agent used” flag is insufficient.

1. **Freeze and admit.** The parent supplies a source-selected snapshot identified by report ID/kind, selected language, source version/digest, assets and translation admission where applicable. Freeze the complete source and component inventory before model work. Hash the vendored skill, references, adapter profile, renderer and dependencies. Treat source prose, links and chart text as untrusted data. No research, network retrieval, translation, or source mutation is available to this agent.
2. **Read and plan.** Load the exact skill text and required references into governing context together with the approved application-profile differences. Supply the full source in deterministic complete chunks if necessary, with explicit read coverage. Ask the model for a schema-validated layout plan referring to immutable component IDs: grouping, approved typography/spacing profiles, page breaks, table partition instructions and asset placement. Do not have it regenerate research prose. Host code resolves references into exact source content and verifies order, all rows/cells, signs, units, footnotes, links and asset identities. Unsupported structures stop explicitly.
3. **Render and observe.** Execute only an allowlisted render tool against a fresh job generation directory. The model receives actual QA diagnostics and component-to-page locations. Tools accept artifact IDs and allowlisted options, never arbitrary shell, executable code, absolute paths, or arbitrary URLs. Existing examples of native tool dispatch are reusable patterns; their research tools and permissive result truncation are not.
4. **Review and one repair.** Perform a fresh semantic-preservation review with complete coverage, then actual page-image review on an admitted vision route. Send readable rendered page images, source figure images when comparison requires them, and page/component IDs. Store page-image hashes, selected model/route, response/usage evidence, findings and coverage. Request crops or higher resolution for unreadable cells/labels; a contact sheet or OCR alone does not establish visual review. Permit at most **one layout repair and two render generations**. Any changed PDF invalidates review of its predecessor; review every page of the final generation again. Limits must cover that second review as well.
5. **Gate and release exact bytes.** The host, not a model `approved` field, evaluates source completeness, machine QA, full semantic and visual coverage, findings, current hashes, job status and budgets. Issue a new automated-review receipt naming the reviewed scope and limitations, then expose only those PDF bytes through the parent's download path. Unavailable vision, missing coverage, unresolved semantics, failed QA, exhausted budget, cancellation or stale inputs produce a typed non-ready result. Existing byte-identical reviewed results may be reused only with complete matching provenance and an explicit reuse record.

A compact application receipt should bind `job_id`, language, source/asset hashes, normalized-content/layout-plan hashes, exact skill/resource/profile hashes, renderer/environment identity, PDF hash, page-image hashes, review-contract version, component/page coverage, findings, reviewer kind/model/actual route, timestamps, attempts and usage precision. It should distinguish `passed`, `failed`, `not_run`, and `unavailable`. Store model review observations and tool results behind the receipt; a self-reported boolean is not the evidence.

The agent may use native tools when supported, or a strict JSON action protocol executed by the same host dispatcher. [`chat_json`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/utils/llm_client.py:667) repairs JSON and may retry; it is not schema validation. Validate every action and its arguments after parsing. A structured text fallback is suitable for layout decisions, not a substitute for pixel review.

## 4. Validation: preserve the distinction between three proofs

| Proof | What can be checked | What it cannot establish |
|---|---|---|
| Source preservation | Independent source-to-component map; exact prose and cell content; ordered coverage; numeric/sign/unit checks; asset hashes; source/output reconciliation. | Matching two inventories generated from the same incomplete normalization does not prove full-source coverage. A source digest does not make its research true. |
| Render integrity | The skill reopens the PDF, compares text within recorded component regions, verifies figure pixels and placements, links, used-font embedding, safe bounds, component overlap, page counts and page numbers. It renders every page to PNG. | Machine checks do not establish preserved meaning, readable raster labels or acceptable visual layout. |
| Automated semantic/visual review | Actual model observations on the complete selected-language source/derivative and every final page's pixels, with recorded coverage and defects. | This is model review, not manual approval, independent expert certification, or proof of factual/investment correctness. |

## 5. Bounds, cancellation and budget hooks

Existing hooks are useful but insufficient for a strict export-job budget:

- [`llm_call_timeout`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/utils/llm_client.py:74) applies per-context HTTP timeouts in `_chat_openai` at line 1045. The native-tool path does not apply that context override. Generic client construction defaults to a 600-second HTTP timeout when no specific Config attribute is supplied; CLI calls use `LLM_CLI_TIMEOUT`, default 180 seconds. Neither is a complete job deadline.
- `chat()` and `chat_with_tools()` have up to three outer attempts; `chat_json()` can invoke chat twice; reasoning-option repair can resend once; SDK retries may add attempts when its retry defaults remain enabled; fallback creates another call chain. A one-call agent step therefore does not imply one provider request. CLI methods accept `max_tokens` but do not forward an output-token limit to their commands.
- [`set_run_context` / `LLMMeter`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/utils/telemetry.py:42) provide job/stage attribution. Set a distinct export job ID in every worker context; do not rely on sole-active-run attribution, which becomes ambiguous with concurrent pipelines. Use an independent client instance per job because `_last_usage` is mutable.
- [`check_budget`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/utils/telemetry.py:403) checks configured global thresholds after successful calls; zero means unlimited. This is not pre-call reservation, a hard cost cap, or accounting for every failed/unknown-usage attempt. Native-tool responses without usage currently record zero; CLI usage is estimated. New receipts must preserve unknown/estimated usage distinctions.
- Cache hits can return before budget checks. [`LLMCache.bypass`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/utils/telemetry.py:554) is available for fresh reviews. If review reuse is allowed instead, bind it to exact inputs/artifacts/skill/contract/route and label the reuse.
- There is no cancellation parameter in the generic client or dedicated cancellation hook in `ReportAgent`. Pipeline cancellation is separately implemented with events and [`PipelineCancelled`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:258). It does not automatically cancel a new export worker's HTTP call or local renderer.

For the parent's job design, require positive configured limits for source bytes/components, source chunks, page count/pixels, model output, model requests including retries/fallback, rendering attempts, concurrency, and elapsed wall time. Preflight the work needed for complete review; if it will not fit, stop with the explicit limit rather than sample or truncate. Existing [`truncate_to_tokens`](/Users/rogerlin/.codex/worktrees/research-pdf-export/DeepResearchForecast/backend/app/utils/token_budget.py:50) is unsuitable for accepted-source completeness.

Keep cancellation/deadline checks before and after every model/tool step and immediately before release. Bound request retries/timeouts by remaining time. Use a cancellable owned renderer process and, where a hard local deadline is required, an owned worker process with process-tree cleanup; do not terminate shared services. A local cancel cannot prove that remote provider computation/billing stopped. If strict token/cost enforcement is required, the current CLI adapter cannot promise it; either adapt its accounting/transport or reject that strict-budget mode. These are proposed integration requirements, not existing proven behavior.

## 7. Practical architecture tradeoff and later acceptance

| Option | Value / cost | Recommendation |
|---|---|---|
| Invoke the installed script unchanged | Strong existing bilingual draft/QA/publish boundary, but forces both languages and its metadata/schema constraints. No agent decisions by itself. | Does not meet selected-language application behavior. |
| Small generic-client agent + source-preserving selected-language adapter + new automated review contract | Reuses current configured clients and skill evidence; requires explicit image admission, bounded execution, schema adaptation and genuine review receipts. | Recommended. Unknown/unavailable vision remains an honest non-ready outcome. |
| Full DeerFlow export subagent | Existing skill mounts, model declarations and image middleware, but introduces harness dependencies, broad tools, independent lifecycle and other model routing/authentication semantics. | Reuse a narrow vision adapter only if materially simpler for the current authorized provider; do not add a full research run. |

After plan approval, acceptance should demonstrate: (1) both report buttons reach the skill-bound agent and selected source; (2) English works with Mandarin absent, while missing/stale selected Mandarin never triggers hidden translation; (3) accepted text/assets survive unchanged, including hard tables/footnotes/figures; (4) actual page-image payloads reach the selected model, with a deliberately visible defect and a clean control correctly distinguished; (5) non-vision and CLI fallback cannot claim visual review; (6) every final page is covered and altered source/PDF/page/skill bytes invalidate receipts; (7) a real model layout decision and, for a defect fixture, a repair driven by tool observations are recorded; (8) cancel, budget, retry and restart paths cannot publish stale/partial artifacts; and (9) clean deployment without the author's skill folder produces exact reviewed download bytes.

Offline transport doubles can prove payload shape, coverage enforcement and refusal behavior, but cannot prove that a real endpoint interprets images. A later authorized real-provider check is needed for that claim. No such check or application test was run in this audit.
