### 11.1 What changed (by defect)
1. **Writer liveness by PID (persistence B1).** `service.status()` decides liveness from this process's own child handle or the launch flock (`world_launch.lock`, held by every child for its whole life and released by the kernel on exit, including across a reboot); the recorded PID is never probed (service `_alive` removed). `run_child` requires the inherited descriptor to hold the exclusive flock (`_hold_inherited_launch_lock`) and takes over with `WorldStore.acquire_writer(..., holds_launch_lock=True)`: an owner recorded by another process is taken over without a PID probe, an owner recorded with this process's own PID stays protected, and callers without the lock keep the old fail-closed probe. SIGTERM becomes cancel-and-release (`_sigterm_cancels`, scoped to `run_child` in the main thread): the child stops at the next causal boundary, records `stopped` / `terminated` and releases its fence. A failure before the fence is logged (`World child … failed before acquiring its writer fence: <code> (<message>)`, i.e. `world_child.log` for a real child) and the projection is left alone, because another launch may own it.
2. **Boundary effects (core B2).** In `kernel._advance`, a scheduled effect or settlement that meets `insufficient_resources` / `negative_quantity` is recorded as `scheduled_<kind>_failed` / `commitment_failed` (details carry the code; a failed commitment is closed, its holds released, nothing moves); scheduled effects are atomic already, settlements are pre-checked on detached copies (`_settlement_failure`). A failed scheduled effect counts as processed (`_scheduled_done`), so it is neither retried nor called overdue. Opening (asOf) effects still raise, a specification defect that preparation must report; a same-instant settlement inside an actor's intent still rejects only that intent.
3. **Provider 429 / 1302 (model-facing B2).** `_dispatch` classifies with `llm_errors.error_status` / `error_code` on the SDK's `APIStatusError` (status 429, or Zhipu code 1302/1303/1305) → `ProviderThrottled` (usage zero: a capacity refusal happens before generation; Retry-After / retry-after-ms parsed); every other failure is unchanged (`policy_transport_failed`, unknown exposure). Each SDK dispatch holds `research_budget.model_call_lease(1)` (loaded through the new `official_data.bridge_module`); a lease that stays full raises `model_capacity_unavailable` before dispatch, also with zero usage. `WorldSimulationService.start` passes `RESEARCH_MODEL_LEASE_DB` to the child exactly as the pipeline passes it to research subprocesses. `policy.call_with_backoff` (at most 3 waits, each min(30 s, Retry-After or 5/10/20 s), stops waiting on cancel) wraps every actor decide on both controller paths and the modeler; the waits stay inside the one reserved attempt, so the slot is not charged. When they run out, the attempt is recorded `throttled` (zero usage, outside the slot's allowance), the run stops with `provider_throttled` (runner status `stopped`, resumable by `start`), and the modeler records its ledger row `throttled` without spending one of its two requests.
4. **v4 admission and unresolved verdicts (model-facing M1).** Fresh admission accepts no review pin (the default) or `actor-consistency-v4` as an explicit opt-in (still with its candidate-repair pin); v1–v3 stay rejected for fresh worlds. A validated revision whose assessment stays unresolved (any review mode) is recorded as before — failed, `consistency_unresolved`, withheld decision and assessment, so the withheld receipt is kept — and the store commits its decision in the same transaction with `consistencyStatus: "unresolved"` (`_revision_decision`); no third call, resume reads it. The world view labels such decisions ("Consistency review unresolved" / 一致性复核未解决) and failed commitments ("Failed" / 未能履行).
5. **Per-round event limit (core M5).** `kernel.event_load` counts events except zero-amount `flow_transfer` / `flow_summary` (still recorded). `_run_intents` no longer re-raises `event_limit`: a group is rejected alone when its events, the events already admitted, and the boundary work it leaves would not fit — this round by an upper bound first and an exact probe (`_boundary_load`) only when the bound does not fit; later rounds it schedules settlements or expiries into by the bound, so they cannot pile up past a later round's limit. Resolution replays staging's admission for proposal communication and reserves its events and offers ahead of other groups, so a recipient is never shown an offer that resolution drops. The store's commit check uses the same count. Boundary work fixed by the specification alone that exceeds the limit still fails the round (configuration).
6. **Resume burns attempts (persistence M2).** When a writer fence advances, every attempt still `unknown` (in flight, or finished with unknown exposure) belongs to a superseded fence and is marked `abandoned` (`_abandon_open_attempts`, rehashing review receipts): it keeps its reservation in exposure, leaves the slot's count, cannot be finished, and its review stage is dispatched again (live-entry rules in `_verified_consistency`). Store schema v2: the review journal drops `UNIQUE(slot,stage)` (plus a slot index); v1 files read unchanged and are migrated row for row on the first writer open; unknown versions still fail closed (`unsupported_store`).

### 11.2 Decisions
- **A throttled request is metered as zero, not as unknown exposure.** An HTTP 429 / throttle code is a definitive refusal before generation; counting each refusal as a full reservation would turn throttling into `run_budget_exhausted`, which is terminal. The classification uses only the structured status and code. Other HTTP failures keep unknown exposure.
- **The backoff lives around the strict transport, not inside it** (the model-facing review's "add classified waiting around it, not inside it"); the transport still dispatches exactly once per call.
- **Attempts finished with unknown exposure are abandoned too** when the next fence starts, not only in-flight reservations: their outcome is equally unknown, and a transport outage would otherwise still end the slot for good. Every abandoned attempt keeps its full reservation, so the run budget bounds repeated resumes. Consequence: the per-slot cap of two now counts attempts with a recorded outcome, so across resumes a slot can see more than two dispatches; README "Each decision slot…" sentence updated.
- **Unresolved commits apply to every review mode** (v1–v4) rather than only v3/v4, so the rule is one rule; the flag is a decision field (visible in analyst/actor results), the assessment stays private.
- **Event budget order: staged communication first.** Alternatives (re-checking communication in resolution order) could drop an offer a recipient had already been shown.
- **Store schema versioning with an in-place migration** instead of re-pointing journal rows (loses which stage an abandoned attempt served) or a side table.
- **The live-evaluation launcher counts capacity refusals** (`docs/handoff/reflexive-world-simulation/run_live_evaluation.py`): without it, a throttling provider would consume every remaining case (`test_world_withheld_diagnostics` made 12 calls instead of 3).
- **No change** to `results.py`, `DEFAULT_LIMITS`, spec hashes or schema constants; OASIS code paths untouched apart from `official_data.data_api()` now delegating to `bridge_module` (same lock, same behaviour).
