## Contract map and early findings

The producer is the received research report, actor dossier, actors JSON and official statistical snapshot. `PipelineOrchestrator` sends report/dossier strings and `_actors_to_context(actors)` to `OntologyGenerator.generate`; the actual ontology request is its `chat_json(messages=...)`. The project ontology and handoff/ontology.json carry the resulting schema. `GraphBuilderService.set_ontology` creates Pydantic entity/edge models and forwards those to the Graphiti runtime registry. The orchestrator must register them again on reuse after a process restart.

Graph ingestion receives sanitized, individually delimited `_graph_research_chunks` and the research date as `reference_time`. `seed_actors` selects the strict actor-intelligence/v1 producer when a current seal is present. That path preflights all actors, aliases, relationships and source support; deterministic graph-scoped UUIDs and a readback manifest bind physical graph state. Unversioned actors follow the older permissive triplet path. `add_text_batches` performs a cast-name filter before sending real EpisodeData to graph.add_batch. Entity resolution and pruning run after ingestion; readback is a separate predicate from successful calls.

Source inspection identifies candidates that still require behavioral evidence:

1. Ontology documents are individually capped before head/middle/tail sampling, so a single long report can lose its middle/tail before the sampler runs.
2. A separate central question only enters general_forecast rules. Social-opinion requests and the schema fallback omit it; the fallback call also drops the actor argument.
3. Official statistical chunks may contain no cast names and be removed by the cast filter despite deliberate upstream inclusion.
4. The permissive relationship extractor accepts aliases, but legacy graph writes use those alias endpoints without canonical label/summary lookup.

Parent-owned candidate: the sealed `_actors_to_context` projection returns after bounded actor claims and does not project relationships, quantitative facts/units, forecast scenarios, risks or standalone source rows. The prose may contain these facts, but that is not evidence that the structured fields reach the ontology request. Ontology reuse and research-generation invalidation must be verified by the parent at orchestration boundaries.

### Access, identity and reuse controls that remain separate

The graph is a modeler evidence plane, not an actor knowledge grant. Qualifiers such as visibility/actor_knows survive canonical claim JSON; their presence in graph storage or embedding input does not establish permission for any actor prompt. Actor-context access checks, fork/seed ownership and report publication policy are owned by adjacent stages. The strict graph seed code assumes the parent already admitted/recomputed the seal; it does not independently prove the receipt's contents came from a live source.

Graph readback validates schema/digest/graph identity, exact required node/edge attributes and labels, summaries/facts, endpoints and duplicates. Only intentional alias-node collapse into its canonical actor is tolerated. Existing tests reject source/provenance tampering, foreign graph identity, duplicate relationships, empty/failed writes and invalid manifests. The new runtime case executes deterministic seeding twice through real facade/dispatcher/writer/models/embedding/storage/readback code; the scripted DB uses UUID upserts, and no duplicate physical nodes/edges appear. This is not a live FalkorDB durability or crash-transaction test.

Ontology freshness is a parent-owned source-only concern: the frozen orchestrator's ONTOLOGY branch at 13659–13661 accepts truthy project.ontology, while _probe_artifact_schema checks that ontology.json has nonempty entity_types. This slice did not execute all upstream invalidation paths and therefore does not claim a stale-reuse behavioral repro. Prior memory of a stricter reuse guard is historical and is not used as current proof. The parent should pair changed-research and unchanged-research resume cases at the actual reuse branch.
