## 1. Recommended bounded change

Introduce an explicitly selected reflexive simulation mode behind the existing pipeline stages, with a typed, immutable result contract shared by APIs, the simulation UI and report generation. Keep research engine selection separate. Show concrete metrics, actor decisions, accepted/rejected actions, commitments and consequences by committed round. Preserve the distinction between simulated state, actor beliefs, source observations and published forecasts throughout storage and presentation.

The first complete consumer slice should consume a short scripted run in each of the three domains through the real admission-to-report/API/UI boundaries, with provider and graph services replaced by strict offline fixtures. The same projections and endpoints must work for all three domains; their metric/action dictionaries and mechanisms differ. This proves integration and declared semantics, not empirical realism or predictive skill.

## 3. Proposed producer-to-consumer contract

The following are proposed minimum semantics, not claims about existing types or final filenames. PLANS.md should reconcile their exact names with the kernel and research/ontology design inputs once, then make one contract authoritative.

### 3.1 Prepared input and engine identity

Persist `simulation_engine` and `engine_version` separately from research engine, social platform, model and forecast effect. Suggested modes are `oasis` and `reflexive_world`; capability metadata determines which UI panels and operations apply. Bind engine, domain mechanism, input generation and effective policy at admission/preparation, and preserve them on resume/fork/research-only continuation.

The initial world contract needs metric definitions (stable ID, type, unit, stock/flow basis, period/aggregation), dated initial values, actor IDs, action capabilities, explicit mechanism parameters, commitment rules and visibility policy. Each initial value/parameter must identify observed source evidence, an estimate, an explicit scenario assumption, or missing information. A source-backed initial value becomes part of a simulated state after transitions; its descendants do not become observations. Unsupported required mechanisms or missing required parameters produce a preparation gap with a concrete reason, rather than silent invented defaults.

Freeze research/ontology/graph identities as provenance inputs. Graph reach or centrality is not a budget, mandate, vote entitlement or physical capacity. Simulated relations/events remain in a simulation namespace and cannot be fed into the observed research graph. A separate simulated graph view, if included later, reads the same committed event/relation projection as the UI and reports.

### 3.2 Minimum read projections

| Projection | Required consumer semantics |
|---|---|
| Run/result manifest | Schema, engine/mechanism versions, simulation and attempt IDs, prepared input hash, consumed research generation, effective forecast policy, seed/sampling metadata, committed round/revision, artifact hashes, terminal reason, validation/coverage status. Run completion, artifact integrity and empirical validation are separate fields. |
| Round/world view | Round ID, simulated period start/end, before/after state references, typed metric values with units/basis, changed relations, causal event IDs and pending commitments. Unknown/unmodeled values have reasons; zero is a real value. Returned metric values carry `epistemic_status=simulated`. |
| Actor decision view | Actor ID, round, observation/view reference, goals/incentives/constraints relevant to this decision, modeled belief changes, selected action or abstention, brief declared rationale and status. Display a bounded explanation record, not hidden model reasoning. Private beliefs are modeled beliefs, not facts about a real person's mind. |
| Action resolution view | Decision/action IDs, action type and parameters, proposer/counterparties, accepted/rejected/deferred status, machine-readable reason plus display text, actual resource reservation/debit and links to events/commitments. Intent and execution are distinct. |
| Commitment view | Commitment ID, originating action, obligated actors, reserved resources, acceptance/authorization conditions, due period, status and eventual settlement/cancellation/failure event. Pending amounts and realized effects are presented separately. |
| Report diagnostics | Frozen result identity, bounded causal chains, selected metric trajectories, pending obligations at horizon, assumptions/gaps and comparison eligibility. Simulated claims reference run/round/action/event IDs and never acquire real-source `[S#]` status merely because the initial state had citations. |

Expose only schema-selected fields. Default report/world views use the public projection. An analyst view may inspect modeled private state only when explicitly labeled and permitted by the view policy; actor observations always use their own visibility projection. Browsing an omniscient analyst view must never change what actors receive on subsequent turns.

### 3.3 API and consistency rules

Retain the legacy `/trajectory` reader and its established response shape. Proposed new surface: one world-state endpoint returning the manifest, round summary, bounded metrics and a commit cursor; paginated decision/action/commitment endpoints using the same cursor and optional actor/round filters. Exact route names are a plan decision, not a requirement to implement four services. A single service-level reader can back these projections and the report adapter.

All pages bind `(simulation_id, attempt_id, committed_revision, projection/view)`. Reads during a new round return the last complete committed revision. A cursor from a previous attempt or incompatible view receives a conflict response; the UI resets deliberately. This avoids pairing a new world snapshot with old action outcomes or partially applied commitments. Client identifiers select validated resources, never filesystem paths.

Differentiate `legacy_unsupported`, `preparing`, `running_no_committed_round`, `available_partial`, `available_complete`, `cancelled`, and `invalid_result`. Missing/corrupt artifacts for an allegedly completed reflexive run are errors, not an empty success response. Domain validity and missing mechanism coverage remain explicit alongside lifecycle status. No provider/graph queries or artifact regeneration occur on GET.

Cap bytes, rows and page size; preserve explicit truncation/next-cursor metadata, reject symlinks/escape paths, and hide arbitrary source/config/private payloads. Unlike the old newest-tail response, a capped new response must let a user navigate to earlier committed history or state why it is unavailable. A withheld private row may disclose a redaction status without exposing its content.

## 4. UX and report behavior

In `SimulationView`, display the selected engine and simulated calendar period. For reflexive runs, the initial view should answer: what changed, which actor action caused it, what remains pending, and what actors do next. Use a round selector with four related views:

1. **World:** metric cards/time series with unit and baseline, changed institutional/coalition relations, and explicit unavailable metrics. Plot capacity/cash/rates/votes with their own definitions; never use a common probability axis.
2. **Decisions and actions:** actor, visible circumstances, declared objective, chosen feasible action, acceptance/rejection reason and realized consequence. Show abstention, inability to act, failed elicitation and rejection distinctly.
3. **Commitments:** due dates, reserved resources, counterparty status and actual settlement. A later response links back to the specific event it observed.
4. **Assumptions and limits:** source cutoff, assumed parameters, mechanism coverage, information visibility and termination reason. Detailed manifest hashes belong in an inspect/download view, not the main user flow.

Keep social feeds available for legacy runs and any explicitly supported social channel; they do not determine whether a concrete action occurred. All labels and error states need aligned English/Chinese text, keyboard navigation, non-color status indicators and a readable table equivalent for charts. Round changes, run changes, view changes and language changes must invalidate stale requests; test A→B→A responses as well as A→B. Stop polling on terminal states, fetch final committed output once, and preserve visible error/partial-state information.

Add a separate **Simulated pathways** report section: dated state trajectory → consequential action → commitment/outcome → subsequent actor response, followed by assumptions and unresolved obligations. Use the same frozen result adapter for main pipeline generation, direct generation, regeneration, chat context and visuals. The report should link a claim to its simulated event, and a starting assumption to its external source when one exists. A real source supporting the initial cash balance does not support a modeled later investment.

Add a corresponding report UI panel instead of populating `fc.scenarios` or official indicator tiles. Current scenario cards consume probabilities at [ForecastReport.vue:952–962](/Users/rogerlin/.codex/worktrees/reflexive-world-simulation/DeepResearchForecast/frontend/src/components/research/ForecastReport.vue:952). Simulated metric paths must not enter that carrier through a compatibility adapter. Captions, downloads, translations, PDF charts and chat responses must retain simulation status, units, date basis and frozen result identity.

Report-side comparisons require common metric definitions, units, periods, initial-state ancestry and mechanism version. Present scenario interventions and parameter differences next to deltas. Compare matched scripted seeds where meaningful, disclose any divergent exogenous draws, and mark incomparable outputs rather than treating absent metrics as zero. An institutional vote share is a vote share; a set of runs' outcome frequency is descriptive sampling output, not a forecast probability.

## 5. Forecast boundary and publication policy

**Proposed initial policy:** allow explicitly labeled mechanism/trajectory analysis under `diagnostic_only`; no simulation-based probability update. Under `no_update`, exclude simulation-derived content from report reasoning and probability generation; the dedicated simulation UI may still display the run with this policy explained. A missing/invalid required result prevents a reflexive report from claiming a complete simulation; optional diagnostics can be explicitly withheld without inventing outcomes.

The existing signal-pack header already requires simulation provenance and forbids probability use, but also forbids action counts/round details broadly ([report_agent.py:3780–3793](/Users/rogerlin/.codex/worktrees/reflexive-world-simulation/DeepResearchForecast/backend/app/services/report_agent.py:3780)). Revise the new adapter's wording so concrete modeled transactions, policies and commitments can be explained with dates and units while retaining the prohibition against treating them as observations or probability evidence. Do not globally turn old social action counts into economic actions.

The clean boundary needs separate inputs and explicit routing, not a prose instruction alone:

- Build/pin forecasts from approved research/official/market/forecast-spec inputs that do not contain the simulation projection. Generate simulation analysis from a separate context after forecast inputs are fixed.
- If spine generation fails, retry or rebuild from that clean evidence pack; never extract new probabilities from mixed report Markdown. If clean input is unavailable, use an explicit unavailable/failed forecast result and the existing publication rules; do not label the mixed-prose fallback safe.
- Apply the same restriction to binary extraction, critique, repair, translation and regeneration. Changing only the simulation bundle must leave probability-producing input bytes unchanged under `diagnostic_only`/`no_update`; test that with captured fake-client calls. Fixed fake replies also permit an exact probability-carrier comparison. This is a deterministic information-flow check, not a claim that live stochastic models return identical numbers.
- Thread the effective run policy into each report/tool/extractor entry point rather than relying on mutable Config. Reject missing policy for required new contracts. Reserve `legacy_prompt` for characterization fixtures, never as fallback when new inputs fail.
- Record diagnostics in their own versioned bundle. The current `sim_adjustment` records shares and deltas without changing scenario probabilities ([forecast_extractor.py:1304–1346](/Users/rogerlin/.codex/worktrees/reflexive-world-simulation/DeepResearchForecast/backend/app/services/forecast_extractor.py:1304)); its name is not evidence that calibration or causal updating exists. Do not fill it with concrete-world outcomes just to preserve the old shape.

Seal the consumed simulation diagnostic bundle and its manifest reference before final report audit. The report publication predicate should bind these bytes as well as existing forecast/prose authority; changed/missing required diagnostics invalidate their publication. Derived charts and localized copies need the same result identity. Reading an old report must never silently render charts from a newer run attempt. Existing post-report ensemble handling deliberately keeps `ensemble_forecast.json` separate ([pipeline_orchestrator.py:9209–9228](/Users/rogerlin/.codex/worktrees/reflexive-world-simulation/DeepResearchForecast/backend/app/services/pipeline_orchestrator.py:9209)); do not mutate a sealed forecast after adding world ensembles.

No simulated outcome may resolve a real forecast or supply a production calibration label. Existing ledger filtering excludes golden/characterization/evaluation rows ([forecast_ledger.py:38–63](/Users/rogerlin/.codex/worktrees/reflexive-world-simulation/DeepResearchForecast/backend/app/services/forecast_ledger.py:38)); a new simulated record class must have explicit rejection/eligibility semantics, because merely choosing another class name is not excluded by that predicate. Prefer keeping simulation evaluation in its own artifact set with no production-ledger call.

`validated_update` is outside this rollout. A later proposal would need a dated target/metric/units/resolution specification, a frozen forecast policy, outcome-blind held-out cases, independent realized observations, declared baselines and scoring/calibration analysis. Passing synthetic mechanics, achieving equilibrium or repeating model draws cannot meet that standard.

### 7.3 Cross-domain realism probes

Use three small domain packs, each with 4–8 synthetic actors and 4–6 declared periods. Each pack supplies bounded mechanisms and a scripted feasible-action oracle; these are illustrative synthetic institutions/economies, not claims about universal behavior. Proposed values and thresholds should be frozen in PLANS.md before implementation.

| Domain | Concrete causal chain | Paired falsification |
|---|---|---|
| Investment/supply-chain | An investor commits funding to a supplier; an accepted contract reserves cash and capacity; a specified construction lead time delays usable capacity; a buyer observes a shortage and reallocates an order. | Reduce available financing below the contract requirement: reject or reduce the investment, retain the shortage and expose the buyer's changed feasible options. A promotional post alone cannot build capacity. |
| Policy/trade | An authorized institution adopts a specified restriction with an effective date; shipment eligibility changes only when effective; an affected importer responds through an explicitly allowed route or substitute. | Remove legal authority or move effective date beyond the horizon: announcement alone does not change eligibility. No generic tariff-to-price or welfare equation is invented; price effects remain unmodeled unless the pack supplies one. |
| Coalition/institutional | Actors negotiate a conditional support agreement; commitments are recorded; the declared quorum/voting rule and actual eligible votes determine passage; a rival observes the result and changes its next feasible proposal. | Withdraw a pivotal member or invalidate a mandate: agreement/announcement does not count as a completed vote; passage changes only under the declared institutional rule. Influence is not a vote entitlement. |

For each domain, run five paired perturbations: binding resource/authority constraint, delayed effect, hidden versus revealed information, material rival/counterparty response, and a semantically irrelevant label/order change. This yields 15 paired checks across the same consumer interfaces. Scripted expected outcomes should be explicit, including when no response is expected because information is hidden or alternatives are infeasible.

Proposed initial acceptance thresholds:

- **Mechanical validity:** zero forbidden accepted actions, zero duplicate settled commitments, zero conservation/authority/visibility violations under each pack's declared rules. Every visible consequential change has an event and mechanism reference; every action has a resolution or explicit pending status. Require 100% reference coverage and per-domain reporting.
- **Reflexivity:** each domain exhibits at least one complete visible chain `observed state → feasible action → changed world → changed next actor observation/options → response`. All preregistered consequential perturbations cause the expected difference; irrelevant perturbations preserve semantic outputs. A narration of a response without a changed state/action record does not pass.
- **Timing:** 100% of commitment settlements respect declared effective dates, lead times and conditions; pending beyond-horizon commitments remain visible. A quiet round must not erase due work or a known future shock.
- **Consumer fidelity:** API, UI, report table and exported metric values/units agree with the same committed fixture; zero missing-to-zero conversions, false observation labels or simulated-to-probability conversions. Compare structured values before localized rounding.
- **Recovery:** interrupted/resumed scripted runs match uninterrupted committed projection hashes, excluding declared nondeterministic metadata such as wall-clock timestamps; no duplicate action/event effects. New-attempt results never inherit old-attempt content.
- **Bounded delivery:** freeze initial caps (suggestion: 100 list rows per page, 1 MiB per response) and measure all fixtures against them; disclose truncation and continuation. Record request counts and load latency on a named test host before setting a production latency target; do not infer live performance from fixture speed.

For subsequent model-driven behavior evaluation, use held-out variants and an independent reviewer who sees world inputs, admissible observations, available actions and resolved effects. Score goal/incentive consistency, feasibility, response to consequences, and explanation/record agreement on a declared 0–2 rubric. A proposed promotion threshold is at least 80% of available points in **each** domain, with no hard constraint/privacy/forecast-policy violation. Freeze case count, seeds, rubric and baseline before running; report disagreements and failure rates. Compare with a frozen-world/no-feedback baseline to show that the feedback loop changes decisions for the intended reason. This assesses behavior under declared assumptions; it does not establish real-world calibration.
