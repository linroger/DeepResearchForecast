# Executable world-v1 boundaries

This implements the approved contracts.md. `contracts.py` is coordinator-owned. Workers must request changes to shared interfaces rather than silently changing them. All quantities are decimal strings, time is UTC ISO, visibility and basis are mandatory. No function here contacts a model or graph.

## Kernel

`stage_interactions(spec, snapshot, decisions, round_index) -> snapshot` stages initial-phase communication only for response observations, without physical mutations. `resolve_round(spec, snapshot, decisions, round_index) -> {snapshot, events, resolutions}` repeats staging deterministically, resolves response consent and direct actions, advances chronological time to the period end, and updates private actor states. It accepts normalized decisions from contracts.validate_decision. No inputs are mutated. Stable event/interaction/commitment identities use generation + intent identity; replay must be exact. Sorting is declared actorId then intent priority then intentId; arrival order is irrelevant.

An interaction is `{interactionId, templateId, proposerId, recipientIds, terms, termsVersion, createdAt, deliverAt, expiresAt, status, visibility, basis, lastResponseRound}`; status is pending/accepted/rejected/withdrawn/expired/superseded. Terms are intent parameters and never a state patch. The initial proposal creates an offer id equal to `stable_id(generationId, intentId, 'offer')`. A counter creates a new offer from the responder to the former proposer, supersedes the old version and uses its own intent identity. No resource hold exists before exact consent. Delivery uses template `messageDelayDays` (default 0), expiry `offerTtlDays` (default 30). The response phase has one slot per eligible recipient; acceptance must identify the delivered pending interaction and exact termsVersion. `defer` preserves it. A public message is nonbinding and never changes authority/resources.

Template `parameters` are privileged mechanism configuration. Actor menus expose only templateId/kind/description/inputs/operations; they must not include global parameters, hidden resource feasibility or private hashes. Inputs declare user-supplied fields: `{field: {type: decimal|integer|string|boolean|actor, min?, max?, enum?, required?}}`. Unknown inputs reject. A supplied account/metric/rule ID never overrides a configured one. Operations: agreement propose/accept/reject/counter/defer/withdraw; message execute; other kinds execute. Actors need both template.actorIds membership and actor.capabilities membership. Responders to a delivered offer may respond even when not admitted as its initiator.

Mechanism parameters (fixed by preparation, with basis):

- wait: none.
- transfer: `fromAccount`, `toAccount`, `amount` or input `amount`; same units; source owned/controlled by initiator. Atomic debit/credit, available balance excludes holds.
- investment: `fromAccount`, `toAccount` (named external expenditure sink), `cost`, `targetMetric`, `delta`, `durationDays`, optional `requiresRule` and `requiredRuleValue` (default true). Debit now, create project commitment, add metric delta once at due time. No undisclosed instant capacity.
- agreement: `recipientIds`, optional `transfers` list of `{fromAccount,toAccount,amount}` (amount may be `$quantity` or `$price` naming validated offer inputs), `durationDays` (default 0), optional `relationId`/`relationValue`, optional `requiresRule`/`requiredRuleValue`. All source account owners must be proposer/consenting recipients. Acceptance by all required recipients reserves each transfer atomically; due settlement releases holds and transfers once. Insufficient capacity rejects acceptance without leaking private balances. Already accepted commitments are grandfathered after later rule changes.
- policy: `ruleId`, `value`, `durationDays`, `authorityIds`; actor must be authorized; delayed rule change is a commitment.
- vote: `motionId`, `weights` actor map, `threshold`, `fromAccount`, `toAccount`, `cost`, optional `targetRule`/`ruleValue`, optional `mandateRule`. Input `support` boolean. Record each entitled actor's independent vote; execute once when threshold and resources hold; no promise counts as a vote. Institution account may be spent only by the declared motion mechanism, not arbitrary actor transfer.
- message: `recipientIds` optional; validated input `text`, bounded by maxMessageChars; declared public/recipient visibility.
- breach: input `commitmentId`, mechanism `penaltyFromAccount`, `penaltyToAccount`, `penalty`, optional `relationId`/`relationValue`. Only an obligated participant may breach; execute stated penalty atomically, release reservations, cancel pending effects once.

Initial/scheduled exogenous events use `{eventId, at, kind: metric_delta|rule_set|transfer, parameters, visibility, basis}` with the same fixed identifiers/values and explicit source account for transfer. They are scenario assumptions, not actor actions. Initial events at asOf must settle before first observation. Overdue input events reject. Event processing sorts timestamp then eventId, applies effects once, integrates flows between boundaries. Flow spec: `{flowId, sourceAccount, targetAccount, ratePerDay?, rateMetric?, limitMetric?, visibility, basis}`. Flow units must match; rate is min(rateMetric or ratePerDay, optional limitMetric), nonnegative, debit cannot exceed available source. Flow records exact interval and actual transfer. No implicit elasticity/production law.

Every event contains eventId, round, at, kind, actorId if applicable, sourceIntentId if applicable, visibility, basis and public-safe description; details carry only permitted outputs. Every resolution contains intentId, actorId, round, accepted boolean, code and actor-safe explanation. A rejected intent must leave no partial state. Unrecognized malformed authoritative configuration fails the round rather than silently becoming wait. State mutations must validate before return. Failed required model slots are controller failures, never reducer wait actions.

## Durable store

`WorldStore(path, spec=None, read_only=False)` context manager. New store requires validated spec; opening existing verifies supplied spec hash if any. Properties/methods: `spec`, `head()`, `history()`, `events()`, `resolutions()`, `rounds()` return detached JSON. SQLite WAL/FULL, no pickle. `acquire_writer(owner_id, pid=None, takeover=False) -> int fence`, `release_writer(fence)`. Live owner cannot be stolen; takeover permits dead owner only. Every mutation checks current fence, including observations, decisions, dispatch and completion receipts.

Stable slot is string `'{round}:{phase}:{actorId}'`, phase proposal/response. `freeze_phase(round_index, phase, actor_ids, fence)` pins required roster exactly. `save_observation(slot, observation, fence)` / `observation(slot)`; `save_decision(slot, decision, fence)` / `decision(slot)`. Existing identical values are idempotent; changed values conflict. Observation round/actor/phase bind to slot. Decisions bind observationId and identity. Methods work only for next uncommitted round.

`reserve_attempt(slot, fence, reserved_tokens=0, reserved_cost='0') -> attempt_id` persists dispatch allowance before network, max two attempts per stable slot including unknown prior calls; enforce run maxTokens/maxCostUsd atomically across concurrent slots. `finish_attempt(attempt_id, status, usage, fence)` records `{tokens, costUsd}`; status succeeded/failed/unknown, unknown retains full reservation, known usage cannot exceed reservation. `budget_summary()` includes reserved/actual/unknown and attempts. Exhaustion never resets on resume. Zero reservations support offline scripted policies only, not network.

`commit_round(expected_round, snapshot, events, resolutions, decisions, fence)` atomically compares current head round to expected_round, validates next snapshot/spec/identity, checks both frozen phase rosters have matching persisted decisions, commits closure including actor/pending/sampling state and events/resolutions. It must reject omitted or substituted receipt sets and duplicate event IDs. No partial writes. Semantic `revision` is digest of snapshot + previous revision + round events/resolutions/decisions (no fence, attempts or wall time). `head()` returns snapshot with `revision` added; revision is excluded from snapshot validation/hash closure on write. `history()` includes initial snapshot and committed snapshots. Derived exports are reconstructible; no export is commit authority.

## Controller and observations

`build_observation(spec,snapshot,actor_id,round_index,phase='proposal')` returns actor-only model and visible world records, eligible delivered pending inbox (bounded fair ordering by lastResponseRound then deliverAt then interactionId), safe options and opaque observationId derived only from this permitted payload. Private beliefs/plans are actor-local. No specHash/global revision/count enters model bytes. `response_actors` uses this inbox plus respondToOffers, independent of decision cadence. Initial actors use `(round-1) % cadence == 0`.

`run_round(store, policy, fence)` reads the one committed head, freezes proposal roster, persists observations and validated decisions, stages interactions, freezes response roster, gathers responses, resolves and commits one round. Policies implement `decide(observation) -> raw JSON dict`; controller reserves each actual attempt. Cached successful decisions are reused on recovery. Failed required slots stop before commit. A scripted policy has no external effects. HTTP adapter must expose exact request bounds and have no internal retry/fallback. Call concurrency is bounded; results sort causally. Cancellation checked before dispatch and commit.

The result reader binds one committed revision, never a blend of mutable exports. Prepared world_spec.json + world_input_manifest.json must be checked before child launch, not silently repaired. Future/unknown engine pins fail explicitly. Legacy requests without a pin retain oasis-legacy.

## Lifecycle integration (coordinator-owned service)

`world_simulation.service.WorldSimulationService` class methods use `root` optional path (default Config.OASIS_SIMULATION_DATA_DIR); `directory(simulation_id, root=None)` validates identity and containment without mkdir. `prepare_model(simulation_id, *, raw_spec, research_report, research_generation_id, research_engine, actor_bundle=None, root=None)` calls the real compiler, creates a new opaque generation, seals files, returns `{spec, manifest, manifest_sha256}`. It never overwrites a prepared generation. Initial modeling may come from explicit `world_spec` run options or an additive research modeling candidate; missing specification is a typed readiness failure, never an unrelated social simulation fallback. Compiler model generation and budget are separate from actor policy slots.

`start(simulation_id, *, root=None, expected_manifest_sha256=None) -> dict` validates sealed inputs and strict HTTP policy before launching `backend/scripts/run_world_simulation.py`. `status(simulation_id, *, root=None) -> dict|None`, `stop(...) -> dict`, `require_complete(...) -> public result`, `fork(simulation_id,new_simulation_id,*,root=None,seed=None)->prepare metadata`. Status dict keys: simulation_id, simulation_engine, runner_status (idle/starting/running/stopping/stopped/completed/failed), current_round,total_rounds,process_pid,current_period_end,horizon_date,error. No Twitter/Reddit flags are asserted. Status derives completion from committed horizon plus frozen result binding, never exit code alone. Child writes world_run.json; SQLite owns causal state. Stop writes cancellation token, observed at dispatch/commit barriers; HTTP requests have pinned <=120s timeout. Fork copies prepared baseline into new identities/stores; neither parent nor completed result changes.

Existing SimulationState adds simulation_engine default oasis-legacy, world_generation_id, world_input_manifest_sha256, world_spec_sha256. Existing SimulationRunner's start/get/stop and relevant cleanup/interview paths dispatch by saved engine pin through this service, converting dict status to SimulationRunState with added simulation_engine. World interviews return explicit unsupported capability without starting OASIS or changing world state. API prepare/start and pipeline PREPARE/RUN use the same service; state pins must match inputs at every admission/completion/reuse. Pipeline world branch skips social persona/config/overlay/evolution/aggregator paths, retains stage authority, and reaches existing REPORT with the real simulation id. Unknown pins fail closed. Legacy absent pins preserve behavior.

Results API is `results.read_result(directory, view='public',actor_id=None,round_index=None,revision=None)`. Public/actor/analyst views are explicit; `revision` is a cursor, stale returns conflict. `results.load_frozen_result(directory,require_complete=True)` checks export byte hash against manifest and one committed SQLite revision. `results.report_context(result)` returns empty under no_update and labeled conditional pathway under diagnostic_only. Every report consumer must use the same frozen reader and no ambient forecast policy override. Results export is explicit writer action, never GET repair.

## Execution envelope ownership refinement

Live validation found model-copied outer actor/observation IDs could be stale even though the synchronous RPC received the correct private observation. The strict HTTP actor adapter now owns those two execution-envelope fields: it captures them from the validated observation bytes before dispatch and binds the returned decision to that request. The model returns intents and optional reflection/rationale/status. Legacy echoed IDs are not authority. Direct/custom policy responses and store writes still undergo strict identity, capability, round and fence checks. Nested actor-update provenance and modeler source identities are unchanged. This is independent design-review approved; implementation acceptance is recorded in the handoff.


## Presentation queue compatibility

New world preparation pins `interactionQueuePolicy: "presented-v1"` before sealing. Only this version uses private root `interactionQueueState[actorId][interactionId]` presentation rounds to fairly order a recipient's overflowing inbox. A valid empty response records presentation without accepting or modifying the offer. The cursor enters only the atomic round result and is excluded from actor and result projections. Absence of the pin preserves the legacy scalar ordering and creates no cursor. Validation never inserts a default; existing input loads and forks preserve the original choice. The 16 permanent controller/store/projection scenarios are in `backend/tests/test_world_queue_fairness.py`; the source-bound historical 36-case semantic comparison is linked in queue-fairness-investigation.md.

## Optional actor consistency review

New generations may pin `policy.decisionReview` to `actor-consistency-v1` or `actor-consistency-v2`; absence preserves the ordinary path. Either pin requires `limits.maxAttemptsPerSlot == 2`. There is no ambient default and no retrofit of saved generations. `review.review_mode(spec)` returns the exact pin, and the effective policy must expose the same `decision_review` before any dispatch.

`StrictHTTPPolicy.reservation(observation, *, feedback=None, review=None)` and `decide(...)` accept a saved normalized candidate in `review`. Review and repair feedback cannot be combined. The original observation remains the user JSON; the candidate is explicitly untrusted system data. The adapter captures request mode, observation and candidate before dispatch. A review reply is exactly `{decision, assessment}` and known usage survives parsing, grammar and assessment failures. `PolicyResponse` carries optional `assessment`; `StrictHTTPModeler` is unchanged.

`review.validate_assessment(value, observation, decision, *, mode=MODE)` requires status `clear|unresolved` and four distinct checks: `goal_alignment`, `conditional_timing`, `quantity_consistency`, `explanation_consistency`. V1 retains its exact `{kind, objectiveIndices, intentIndices, evidencePaths, explanation}` entries and reference validation. V2 uses exact `{kind, explanation}` entries, rejecting reference fields and extras. Both require nonempty explanations of at most400characters. Server hashes bind the whole original observation, candidate and final decision in both modes. These bindings establish scope, not selected evidence citations or semantic truth.

The store adds a private consistency journal only when initializing a pinned generation. `consistency_state(slot)` and `consistency_receipt(slot)` validate hashes and stage/attempt linkage. `reserve_consistency_attempt(slot, stage, fence, reserved_tokens=0, reserved_cost="0")` reserves `candidate` then `revision` in the same stable slot, using the original transactional budget and fence. `finish_consistency_attempt(attempt_id, *, status, usage, fence, decision=None, assessment=None, error=None)` atomically saves stage payload and usage; a successful revision alone writes the final decision and requires `clear`. Direct legacy writes cannot bypass this admission. Audit data remain outside actor/public projections.

An unusable candidate or failed/unresolved revision stops before world commit. There is no replacement allowance, third call, forced wait or reset on reopen. A saved candidate with no reserved revision can resume that revision; a saved final is reused; a reserved unknown stage cannot be repeated. New-mode budget receipts distinguish candidate/revision purpose and safe error codes. Old stores, cached decisions and rejected-intent replay retain their prior semantics. The executable source and tests are linked in the [consistency report](behavior-rerun/semantic-consistency/REPORT.md).
