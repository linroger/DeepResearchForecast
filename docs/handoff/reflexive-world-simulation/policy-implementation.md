## Confirmed interface and plan

The coordinator confirmed `StrictHTTPPolicy(spec, *, client=None, pricing=None)`, `external=True`, `reservation(observation) -> {tokens: int, costUsd: decimal-string}`, and `decide(observation) -> controller.PolicyResponse(rawdecision, usage)`. The controller import is lazy. `PolicyFailure` is a sanitized `WorldError` carrying `usage` when a response has accountable metering; the controller owner will consume it even when response parsing fails.

The specification's `policy` pins `provider`, `model`, `baseUrl`, `timeoutSeconds` and `maxInputTokens`. Its `pricing` record pins the same provider/model/endpoint, USD input/output rates per million tokens, context/output bounds, framing overhead and output-limit semantics, with dated source metadata. Optional constructor `pricing=` is an equality assertion against that pinned record, not a replacement outside the durable specification identity. The metadata is required; prices, context sizes and billing guarantees are never guessed. The coordinator explicitly confirmed the policy schema before implementation and required canonical specification binding.

Implementation order is preflight/byte accounting, one-dispatch SDK transport, strict response parsing/accounting, then fake-SDK and actual-SDK/mock-HTTP verification. Reuse Config's HTTP-provider metadata and the installed OpenAI-compatible SDK, avoiding LLMClient's retries, fallback and telemetry. The exact message serialization must contain only the supplied actor observation and a fixed response instruction.
