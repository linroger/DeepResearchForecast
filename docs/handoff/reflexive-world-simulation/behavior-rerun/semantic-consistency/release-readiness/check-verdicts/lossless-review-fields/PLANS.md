# Lossless private review fields — proposal, not released

Observed phase17 structural evidence: seven known check-field rejections retain four object checks with kind/verdict present. Five have one unrecognized additional member beside the required fields; two have explanation absent and one unrecognized member instead. The unknown names and values are not retained and cannot be presumed benign, explanatory or semantically correct. Historical failures remain failures.

The proposed remedy is an explicit new actor-consistency-v4 protocol that keeps action/control fields strict while retaining all parsed non-control review content for audit. It is not a permissive drop-extra-fields parser, a guessed field alias, a fabricated explanation or a semantic-clear override. Before implementation, independent design review must approve the concrete contract and phase17 must close.

Preferred model wire can remain the existing v3 prompt and exact decision/assessment outer envelope with assessment.checks array. Fresh HTTP v4 normalization alone would require exactly four objects, one valid unique kind per dimension and one explicit enum verdict per check. It would pack EVERY other parsed member into a canonical private fields object, without dropping, truncating, concatenating, interpreting or inventing values. A missing explanation name is not filled with invented text; its actual alternative content remains under its original name. Empty commentary, invalid types, excessive bounds or ambiguous control material reject and retain known metering. Exact commentary bounds and reserved-key exclusions need to be frozen in the contract. Candidate actions, intents, state updates, provenance and world mechanism validation remain unchanged.

Canonical v4 assessment would have exact checks, with each check exactly kind/verdict/fields. The shared canonical validator, aggregate-status helper, controller, store/reopen, directed evaluator and valid-unresolved private retention must agree. Normalization runs only on fresh HTTP output, never cached decisions or stored replay. V1/V2/V3 validators and saved runs stay unchanged. Aggregate clear still requires all four explicit consistent verdicts; unknown/inconsistent remains withheld. No third call, budget change, action invention or private review data in actor observations, world effects or forecast evidence.

All parsed commentary must be retained losslessly within existing strict JSON/NFC semantics and bounded new limits. Human/independent-agent qualitative review must inspect every retained member, including potentially contradictory or irrelevant fields. A valid format is not proof of semantic correctness. The fresh confirmation and full36 gate keep exact action expectations, thresholds, denominator, contrasts and qualitative requirements; old invalid rows cannot be regraded through v4.

Acceptance must prove strict controls and limits, preservation of every non-control member, arbitrary data cannot become actions/authority, no hidden-data projection change, fresh-only normalization, canonical idempotent store/reopen behavior, incompatible-mode rejection, known metering and two-call persistence. Preserve v3 actual request bytes where practical to isolate acceptance/audit representation from prompting. New fresh admission would require the evaluated v4 pin only after its offline tests, independent review and complete behavior gate; default remains legacy until then.

Budget remains original total40 minus all closed conservative exposure. A new diagnostic or confirmation needs a fresh source-bound preregistration; full36 remains unauthorised. This proposal has no runtime edits or provider authorization.
