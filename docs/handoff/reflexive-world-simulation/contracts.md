# Proposed actor–world contracts

**Status:** Design for approval; no types, runtime or tests in this document are implemented.
**Authority:** [PLANS.md](PLANS.md). All implementation workers use this vocabulary; M0 freezes machine schemas, canonical serialization vectors and fixture instances before dependent code lands.

## 1. Ownership and identity

The pipeline owns admission and its six stage transitions. A selected simulation engine owns advancement of that simulation. For `world-v1`, one fenced child/controller is the world writer; platform adapters, LLM tools, Graphiti, JSON exports, the API and reports cannot write authoritative world state.

Retain admitted simulation and actor IDs. New event, action, agreement and decision IDs are opaque typed identities allocated once and persisted, not guessed from names or content. Stable idempotency keys bind `(simulation, prepared generation, round, phase, actor, slot)`. Graph UUIDs, platform user IDs, represented organizations and acting representatives have explicit mappings. Hashes identify content, not business identity or access permission.

New external contracts use `lowerCamelCase` fields and declared aliases to internal Python `snake_case`, consistent with ADR 0002. Existing legacy JSON retains its current format. Versioned canonical serialization forbids NaN/Infinity, uses deterministic key/Unicode/date/quantity rules and golden vectors. Quantities have explicit units and fixed precision/rounding policies; unrelated unit dimensions cannot be combined. No silent unit conversion is permitted.

## 2. Minimum records

| Contract | Required contents and authority |
|---|---|
| `simulation-world-spec/v1` | Engine/mechanism/parameter versions; research-generation and actor-model bindings; cutoff, horizon and decision periods; variable definitions and units; initial facts/resources/assets/relations/rules/projects; participant/cadence policy; action catalog; exogenous event/sampling model; assumptions/gaps; visibility; budgets; outcome predicates. This is immutable after PREPARE. |
| `simulation-actor/v1` | Canonical identity and mandate; objectives/values/preferences/incentives; modeled beliefs; resource/asset references; action capabilities; hard constraints and soft obligations; relationship/commitment references; channels/observation rights; decision cadence; provenance and readiness by action family. Initial model is immutable; dynamic state is separate. |
| `actor-state/v1` | Current beliefs and uncertainty, observed-event memory, plans, goal progress, permitted priority revisions, perceived relationships and decision history. Every update cites observations or decisions; it cannot create world resources or authority. The allowed update whitelist permits beliefs/plans, while goals, values, incentives and priority rules remain immutable unless a declared revision rule and its triggering evidence authorize a specific change. It cannot rewrite preferences after the fact to excuse an action. |
| `world-snapshot/v1` | Simulation/generation/round/time; typed values and their definitions; resource accounts and reservations; asset/project/rule/relation versions; pending commitments and interaction envelopes (offers/messages/delivery/response queues); actor-state references; causal head and sampling state. The entire closure commits together. |
| `actor-observation/v1` | Actor-local view revision, simulated decision time, permitted own/public/private facts, messages/offers, uncertainty and available channels. Modeler-side audit binds full world/model/policy/visible-byte hashes; the actor body excludes hidden global hashes, paths, counts and facts. |
| `action-template/v1` | Stable semantic verb and version; actor/target kinds; typed parameters/units; known prerequisites; authority/resource requirements; consent and timing rules; visibility; registered mechanism reference. A template grants no facts or powers by itself. |
| `actor-decision/v1` | Actor, decision slot, observation/view and menu references, selected intents or explicit wait, bounded belief/plan updates, observation references and concise declared rationale. An envelope binds audit hashes outside the visible model body. |
| `action-intent/v1` | Template/version, proposer and represented actor, bounded parameters, targets/counterparties, conditionality, priority and optional atomic-bundle ID. It cannot contain arbitrary state patches or another party's acceptance. |
| `action-resolution/v1` | Intent ID; accepted/rejected/deferred status; mechanism and reason; private/full and permitted actor-visible explanations; actual reservations/effects or pending commitment IDs. Valid rejected action is distinct from failed decision generation. |
| `interaction-envelope/v1` | Stable offer/message and negotiation identity; exact terms version; sender/authorized recipients; logical creation, earliest-delivery and expiry times; withdrawal/supersession and delivery/response status; persisted fair queue order; links to acceptance or later commitment. An unaccepted offer is not an obligation. |
| `world-commitment/v1` | Stable ID/version, source action, parties and exact accepted terms, resource holds, prerequisites, effective/due time, expiry, cancellation/breach rules, status and settlement/failure events. Acceptance of a different terms version does not bind a party. |
| `world-event/v1` | Event/parent IDs, mechanism, actor/counterparty refs, occurred/effective/available times, visibility/recipients, before/after field references and balanced resource effects. A speech event records a statement; it is not automatically its stated consequence. |
| `world-round-commit/v1` | Round/attempt/fencing identity, pre-state hash, all admitted decision/response receipts, ordered events, post-state/actor-state/commitment/interaction-queue/randomness hashes, validity and committed time. It is the world advancement boundary. |
| `world-result/v1` | Engine/input identity, final commit, time/horizon coverage, lifecycle/validity/empirical-validation status, units/metric definitions, artifact digests, unresolved obligations, assumptions and effective forecast policy. Consumers read one committed result revision. |

Behavioral/data fields carry separate `basisKind` (source claim/report excerpt/scenario assumption/simulation event), `evidenceType` (fact/actor statement/inference/contested/unknown), and `valueStatus` (specified/bounded/contested/unknown/not applicable). Collection fields distinguish specified, known empty, unknown and not applicable. Source support and source-publication time do not automatically confer actor observation or factual sincerity.

## 3. Preparation and model readiness

Research produces modeling candidates with exact claim/span references and explicit gaps. Deterministic adapters validate identity, units, time, scope and mapping rules. The compiler may use a bounded structured model call to suggest a world model, but accepts only registered mechanisms and schema-valid parameters; it cannot install generated code or invent source support.

Sealed legacy actors retain their original contracts and source hashes. V3 candidates use their unsealed research evidence grade; they receive new scenario-scoped model/identity bindings without counterfeit legacy seals. Goals can derive from admitted motivations/incentives/plan claims with recorded mapping rules; unknown goals remain unknown. No liquid cash is inferred from asset value, no authority from centrality, and no capacity from a statement of ambition.

Readiness is per actor/action family and whole model. A family missing its own authority or required physical parameters cannot execute unilaterally. A valid information/authorization request or explicit wait can remain available. When an entire required mechanism is absent, PREPARE returns a typed modeling gap. Approved scenario assumptions can fill selected gaps and are included in sensitivity inputs; they do not establish empirical readiness.

The prepared manifest binds all new model files, exact source generation, actor roster/mappings, role/visibility projection, mechanism/policy versions and assumptions. Runtime admission rechecks the same bytes before model/process work. A changed model gets a new prepared generation; removing new metadata cannot downgrade a corrupt world run into legacy compatibility.

## 4. Exact round semantics

`S_t` is the committed world at decision time `t`, including all admitted effects through that boundary. Initial `S_0` is the cutoff snapshot. Each round advances `(t, t_next]`; pre-existing scheduled effects due through the opening boundary at `t` are already in that snapshot and never applied twice. New intents may have immediate effects at the same simulated timestamp after observation; ordering uses `(simulatedTime, phase, sequence)` so those effects belong to this round's resolution, not the opening view.

1. **Select and freeze proposal participants.** Apply fixed cadence and triggers based on each actor's permitted information. Record intentional nonparticipation. Hidden events cannot wake an actor in a way that leaks otherwise invisible information.
2. **Project observations/options.** Persist the exact visible bytes and decision slots. The action menu uses permitted information and own known bounds. Unknown counterparty facts yield conditional requests, not hidden-state-based menu removal.
3. **Collect proposals.** Each selected actor has a separate bounded context and at most one accepted response per slot. Initial cap proposal is three intents per phase, one decision slot and one later response slot per actor/period. Each slot allows at most two actual provider attempts total, including fallback/repair/SDK retry; a shared budget prevents hidden retry multiplication. Explicit wait, inability to act, malformed response and provider failure have distinct statuses.
4. **Deliver offers and collect responses.** Batch proposal disclosures according to their channels, then freeze a recipient response participant set and view against the same physical `S_t`. The pinned default response trigger is `onDeliveredOffer`: an admitted actor with response authority may receive a same-epoch response slot even if it was not scheduled for an initial proposal. Only actually eligible, permitted deliveries trigger it; cadence/channel exceptions are explicit. Both phase rosters remain within the admitted actor universe and run budget. A deferred/ineligible recipient is not a failed required responder. One bounded response phase can accept/reject eligible exact terms or issue a counteroffer. A counteroffer needing further consent remains pending until another epoch. No unrestricted conversational loop or arrival-order advantage is introduced. The initial inbox cap is 20 offer/message items per actor per period, each bounded to 1,200 characters plus its structured fields; excess items remain pending under a pinned fair ordering/expiry policy, never silently accepted or discarded. Required terms and constraints are never truncated into an apparently executable offer.
5. **Resolve joint feasibility.** Check exact IDs, scope, capabilities, own and joint resource limits, institutional approval, consent/terms, prior reservations and prerequisites. Actor-declared action priority and domain conflict rules decide allocation; tie-breaking is pinned and draws are recorded. Atomic bundles are all-or-nothing. Ordinary independently executable intents have separately recorded outcomes.
6. **Stage and advance effects.** Reserve resources for accepted obligations, apply allowed immediate effects, and evolve modeled processes through the interval. Process due work in explicit effective-time/dependency order. Flows are calculated between events under the domain rule; capacity becoming usable halfway through a period must not operate for the entire period. End-of-period effects affect the next decision epoch. Counterparty behavior is never synthesized as automatic consent.
7. **Validate and commit.** Check resource balances, units, references, domains, actor-state updates and event closure. Atomically commit `S_(t+1)`, actor states, decisions/resolutions, scheduled work, draws and head. Only then publish the next view/progress and release the next round. At the terminal horizon, settle work due through that boundary and publish its state without creating an extra actor decision epoch.

A required actor's missing, malformed or failed response prevents the round from committing. Retry only failed/missing slots within the pinned attempt budget using persisted observations and successful peer responses. Exhaustion ends with resumable failure. Explicit wait/all-abstain or deliberately empty participation still advances due work and background processes. Late responses from an older slot/generation cannot be applied.

Decision-time granularity is part of the model. If the requested horizon and critical decision deadlines cannot fit the run's round budget, preparation reports that conflict. Physical substeps do not falsely imply that actors responded before their next declared decision epoch. Horizon completion retains obligations due later; it does not force their settlement.

### Durable negotiation and delivery

Every unaccepted offer, counteroffer and delayed message is persisted as an interaction envelope in the committed closure, or reconstructible exactly from its committed events. Inbox overflow keeps its logical FIFO/declared tie-break position and expiry state across restart. No resource hold exists before acceptance unless a named offer-hold mechanism explicitly reserves it. A later acceptance rechecks current authority, exact terms/version, expiry/withdrawal and joint resources; obsolete consent cannot settle a changed offer.

A positive channel delay makes a newly sent item ineligible for the same decision-time response phase. It becomes available at its declared time and is observed at the recipient's next eligible decision/response epoch. Offers whose zero-delay disclosures are used within a tentative round are bound to that round's observation/response receipts; a failed round does not publish them as committed events. Required response slots are frozen only after eligible delivery selection. Valid deferral/decline preserves or closes the offer according to its declared rule; missing required provider responses follow the failed-round rule.

Actor policy invocations are stateless transports over explicitly persisted actor memory. A failed attempt cannot silently retain an uncommitted message in an opaque provider session or CAMEL conversation. Raw belief updates and full rationales remain actor-private by default; public explanations are separately projected from authorized content.

## 5. Resources, institutions, communication and uncertainty

Resource transfers require explicit from/to accounts with compatible units and sufficient unreserved balances. Sources/sinks/production/depreciation are named mechanism effects, not unexplained conservation exceptions. Reservation and settlement are separate; repeated delivery IDs cannot settle twice. Funds/stock held for an accepted obligation cannot be spent by another intent.

Institution rules define who can propose, authorize, veto, execute and delegate. A proposed rule and its announced implementation date remain pending until its approval/effective conditions hold. A speech event cannot change legal authority or add a vote. Relationship changes distinguish assertion, accepted agreement, actual obligations and perceptions. A supplier may also be a competitor; an ally may refuse a request.

Soft obligations and norms can be breached only through explicit modeled actions/mechanisms, with stated detection, enforcement, reputation or contractual consequences. Physical conservation and unsupported power cannot be bypassed by a story about willingness. Such rules are scenario assumptions unless grounded and validated; the engine does not claim universal compliance or universal misconduct.

Actor beliefs can differ from simulator state and from other actors' beliefs. Observation of a rumor proves the rumor was received, not its content. Delivery delays, selective disclosure and subjective confidence are retained. Global modeler uncertainty or final outcome probabilities do not enter actor input unless a specific actor-visible source supports an appropriately labeled belief.

Uncertain parameters/events are sampled only by the pinned scenario model, with explicit distribution/alternative/correlation assumptions and recorded draws. No arbitrary LLM-generated shock or probability is silently accepted as physics. The pure reducer takes recorded draws; replay does not make model/provider requests. Same accepted proposals, mechanisms and draws produce the same semantic state regardless of task arrival order.

## 6. Store, fencing and derived files

Use one SQLite database per simulation world generation, with versioned tables for models, round attempts, actor observations/decision receipts, external-attempt reservations, interaction envelopes/delivery queues, commitments/events, snapshots/actor state, RNG records and the committed head. Use WAL journaling and synchronous=FULL on a local filesystem; schema, integrity checks and recovery/export behavior are frozen and fault-tested in M0/M1. The result binds canonical logical records, not mutable SQLite/WAL file bytes. There is one writer; model calls occur outside write transactions. A transaction compares the expected prior head and current fencing generation before applying effects. Tentative observation/decision/attempt writes also require the current fence. Canonical semantic hashes exclude wall-clock, attempt and fence audit metadata while preserving causal/model identity; the membership is fixed in M0 golden fixtures.

Writer takeover follows process-identity/liveness checks and advances the fencing token. A stale process or duplicate commit cannot mutate the current head. Reusing a completed world is read-only. Policy responses may be recorded before a round commits; they are tentative inputs and never displayed as realized effects.

Snapshots/JSON summaries and chart/report/API projections are derived. A committed database head plus an idempotent export cursor lets the exporter repair a crash after commit without repeating actions. Public readers never repair on GET. Completion requires a validated final head and result manifest, not just process exit or an old platform event. Export integrity/durability and actual process cancellation are tested separately.

Resume uses the last committed closure and durable decision slots. Replaying recorded commits requires no LLM call. Recovering a missing unpersisted provider response may call again; accounting records that attempt. No claim is made of exactly-once external provider execution or restored hidden model cognition.

### Enforceable model-call budgets

World-mode preflight admits only an adapter that can control actual request dispatch, retries/fallback, bounded output and actor context. Reuse a supported existing HTTP provider with SDK automatic retries disabled and all fallback/repair attempts routed through the same adapter. An opaque CLI transport is unsupported in strict-budget world mode until these capabilities are demonstrated; a CLI subprocess is not counted as one proven provider request. This is an engine capability check, not a global provider migration.

Before every external request, reserve one durable allowance under the stable decision-slot identity, checked against the current fence and run/batch budget. The initial cap is two actual provider attempts per slot across original calls, retries, fallback and model-assisted repair. Record reserved/dispatched/succeeded/failed/unknown outcomes. A crash between reservation/dispatch/result recording leaves ambiguous allowance conservatively consumed, without labeling it measured billing. Resume retains counters and successful peer responses; an exhausted slot remains exhausted. A larger allowance needs a new explicitly authorized specification/generation and retains the old accounting history. Replay/cache hits make no new external attempt and are labeled separately.

A hard token/cost ceiling requires conservative reservation for every in-flight request, including the full enforceable output bound and a validated input/pricing upper bound. If a transport cannot bound billed exposure, the engine cannot claim or admit it under that hard ceiling. Actual, reserved and unknown usage remain separate. Default promotion does not bypass this capability rule.

## 7. Public projections and report/forecast use

Proposed endpoints under the existing simulation API are `/<id>/world`, `/<id>/decisions`, `/<id>/world-actions` and `/<id>/commitments`, backed by one shared reader. Final exact route names are frozen in M0 alongside existing API collisions. A cursor binds simulation, prepared/attempt generation, committed revision and view. Stale cursors conflict explicitly. Default bounds are 100 rows/page and 1 MiB/response, with real pagination and no hidden missing-to-zero conversion.

Default world/report projections are public. Actor views use exact recipient scope. An explicitly permitted analyst view can inspect modeled private state while preserving its labels. Hidden row counts/identifiers are omitted unless their existence is itself public. Actor tools have a server-bound actor identity; an LLM cannot select another actor's view by supplying an ID.

The result reader supplies the same frozen public simulated-pathways carrier to pipeline, direct report generation, regeneration, report chat, charts, translations and exports. It binds the consumed result in report/publication metadata. Modeler-only diagnostics remain separately permissioned. A required new-engine result cannot disappear through a legacy optional-argument fallback. Simulated outcomes are never written as observed-source claims or production outcome resolutions.

The probability-input builder uses only pinned external research evidence and admitted forecast inputs under safe policies. No-spine and missing-research paths do not re-extract from simulation-bearing prose; if no clean input supports a required structured forecast, the forecast is unavailable/failed under its existing publication rules. The effective policy is passed explicitly from the run. `diagnostic_only` allows labeled pathways in analysis; `no_update` omits them from report reasoning. Multiple simulated paths are conditional outputs; promotion to a calibrated probability update is separate from this feature's mechanical completion.

## 8. Compatibility and capabilities

Pin engine/version/model generation on new admission and carry it through research-only continuation, scenario forks and extra-seed helpers. Missing engine metadata on historical runs means legacy OASIS; unknown declared engines/versions reject. New-engine corruption never invokes old missing-file tolerance.

Fresh world forks/seed runs have child-owned writable stores and inherited immutable source/model ancestry; they cannot share mutable world databases. The initial product preserves the existing fresh-from-baseline scenario-fork meaning. Mid-round interactive branching is not a prerequisite for this release; offline counterfactual tests can replay recorded inputs into a new independent run.

World-mode interviews, when enabled, are bounded read-only statements against an identified committed actor view; their output is stored separately and labeled simulated. Interview/close cannot change the world hash. Social-platform operations are explicitly unsupported on world runs unless supplied by a later channel adapter. Optional OASIS presentation must not independently advance causal state; the initial release needs no OASIS social loop to run world actions.
