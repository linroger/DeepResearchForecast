# Unified translation architecture

**Date:** 2026-10-26 (Asia/Shanghai)
**Status:** Approved by the user; implementation in progress.

## 1. Problem and intended outcome

The request is now a system redesign. The current engine already has useful Markdown parsing and source-bound semantic receipts, but lifecycle ownership is split: ReportManager runtime JSON and TaskManager, research-route inflight sets/status files, artifact-translation caches/inflight workers, and independent Vue polling controllers. TaskManager is process memory. The shared provider gate is process-local. Document retries have no durable candidate/section input, so work that passed20/22 or21/22 section reviews can be repeated wholesale. UI flags such as available, partial, generating and can_generate are derived differently across surfaces. These are architectural causes, not isolated button defects.

The replacement has one translation service and one frontend job controller. Artifact-specific code only chooses source prose, supplies its immutable context, and assembles the result. The service owns execution, persistence, resumption, review, status and error classification. A single artifact resolver supplies the accepted language version to the UI and PDF renderer.

## 2. Invariants

1. Canonical research/report/simulation data is immutable. Typed facts, probabilities, object IDs, dates in typed fields, URLs, code, citation identities and visibility policy remain copied or validated against source. Natural-language factual equivalence is still independently reviewed.
2. A result is admitted only for the exact source, target language, context, visibility scope and validation version it was checked against. A model's claimed success cannot override structural or identity failure.
3. Persist completed work before advancing its stage. A review transport/protocol failure keeps the translated candidate; a semantic rejection requests bounded content repair. An accepted unit is never regenerated by ordinary Retry.
4. Readers and downloads never start provider work. POST start/retry/refresh/stop is the explicit mutation boundary. Reloading a page reconnects to a persisted job.
5. Source snapshots, worker ownership and published output are distinct identities. Late worker results cannot commit after ownership or source changes; late browser results cannot overwrite a new selection.
6. Whole-document publication requires complete admitted coverage. Overlays may display reviewed partial coverage with source fallback and an explicit pending count. Coverage is measured against the entire requested inventory, never only the first N entries.
7. A failed replacement leaves the previous accepted generation intact. Readers/exporters use one immutable generation, not a mixture of independently changing files.
8. A crash after a provider request may leave its billing/outcome unknown. The service records that uncertainty and counts the attempt against the configured budget; it does not claim exactly-once remote execution.

## 3. Source adapters and inventories

Create backend/app/services/translation/ with explicit contracts, inventory adapters, store, engine/executor, service and artifact resolver. Keep model_translation.py and translation_tools.py as thin compatibility entrypoints where required during migration; there will be only one active execution implementation after cutover.

Adapters cover:

- Forecast-report Markdown plus separately named forecast/dashboard/caption fields.
- Research-dossier Markdown plus its structured public display projection.
- Graph summaries and facts from an exact graph revision or frozen inventory digest.
- OASIS and World-v1 visible projections, including personas/feed, world-state provenance and permitted public/actor/analyst views.
- The completed simulation after-action record, through the Simulation tab's same language control. This is included in the unified redesign because it is the default completed-run view; translating only the live view would leave the tab incomplete. Stored record facts and provenance stay canonical.

Every adapter returns a frozen SourceSnapshot and an ordered inventory of WorkUnits. Identity fields include artifact kind/owner, canonical source digest, target language, source language, visibility/view context digest, adapter version and validation-policy version. Each unit has a stable semantic locator, exact source text digest, immutable-carrier signature, context digest and render position. Unit identity must include source text, not merely a graph UUID or section number. Reuse remains artifact- and visibility-scoped; no new global cross-report semantic cache.

Markdown is parsed into a document structure. Normal translation requests contain coherent sections, the document outline and terminology context. Large sections split at real block boundaries; large tables can be processed as bounded row groups while preserving their original structural identity. Code and non-prose carriers are copied, not charged to the model. The adapter must preserve reference/footnote scope and verify the reconstructed whole document. No dropped tail, arbitrary text clipping, or hidden token-rewriting pipeline is allowed. Truly unsupported atomic size is rejected explicitly at admission, not endlessly retried after accepting the request.

Structured adapters declare translatable fields and fixed typed fields. Avoid broad recursive guesses about whether every key called type, category or provenance is prose. Visible explanatory provenance text is translatable; structured provenance IDs/hashes are immutable. The extraction contract is shared with the render projection so newly displayed fields cannot silently escape coverage.

Browser requests identify the resource and current view. The backend resolves its permitted source snapshot through existing resource/visibility readers. A client-supplied digest is a consistency check, not authority to read hidden artifacts or arbitrary filesystem paths.

## 4. Durable work and ownership

Use a versioned SQLite store under Config.UPLOAD_FOLDER/translations/jobs.sqlite3, relying on the standard library and existing local SQLite deployment patterns. It owns job and work-attempt state; accepted publication remains independently verifiable from immutable artifact generations. No external database, broker or task service is required. The current global TaskManager may expose a compatibility summary but is not translation authority.

Minimal logical records:

| Record | Purpose |
|---|---|
| jobs | Resource/source/scope identity, mode, state, budgets, requested time, current worker fence, source snapshot reference and published generation |
| units | Ordered source entries, current candidate and hash, validation/review state, accepted receipt and attempts consumed |
| attempts | Stage, unit/batch identities, ownership fence, start/end, safe outcome code, observable call/usage counters and unknown outcomes |
| artifacts | Immutable published generation identity, manifest digest, language and admitted source identity |

Use short transactions and uniqueness constraints for idempotent start/resume and checkpoint writes, bounded busy handling, and one connection per worker. Initialize the elected scheduler through the explicit application lifecycle, never module import. Exclude the shared store from per-run cleanup. If the coordination database is unavailable, new mutations fail explicitly while independently validated accepted publications remain readable. Never hold a database transaction across a provider call. A single-host dispatcher holds an OS advisory ownership lock; job claims use monotonically increasing fencing tokens. Every checkpoint and publication attempt compares its current fence and source identity. Do not steal ownership solely because a clock-based heartbeat is old while the live process still holds the lock. Provider requests have bounded timeouts, and cancellation takes effect at a durable boundary.

A restart reconciles abandoned local attempts without invoking a provider from GET. Previously accepted units remain accepted; persisted unreviewed candidates resume at review; unknown remote attempts remain explicitly counted. Interrupted jobs present a Resume action. Normal reconnects and duplicate POSTs do not create competing jobs.

Existing FIFO provider admission remains the local translation call cap. Only the dispatcher owns new translation workers after cutover, so multiple Flask workers cannot each create a competing queue. Reuse established lease/locking primitives where their contracts match; do not refactor unrelated research or simulation schedulers. Account-wide quota used by other applications remains a provider limitation, not something this store can guarantee.

## 5. Translation pipeline

A unit progresses through pending → candidate_saved → structure_validated → review_pending → accepted. Rejected candidates may enter repair_pending once, then must pass structure and a fresh review. Transport/protocol failure is an attempt outcome, not an instruction to regenerate every candidate. Terminal states retain the safe error, exact stage and retry eligibility.

Batch by estimated input/output token cost, item count and compatible context, with explicit ceilings. Preserve raw readable source meaning in model prompts. Separate request parsing from payload validation. Detect duplicate keys, ambiguous identities, missing entries, wrong field types and truncated output. Accept independently valid expected entries when the response can be unambiguously mapped; retry only missing/invalid entries. Harmless presentation wrappers may be parsed deterministically, but unknown mappings or missing review flags cannot be guessed into success.

For review, persist the candidate first and submit source/candidate pairs. An invalid reviewer response retries review only. A negative semantic verdict supplies bounded repair feedback for that unit only. A quota/cooldown stops admission and records a retry time; an explicit refusal remains a separate outcome. No regex rewrite or relaxation of receipts may manufacture successful Mandarin.

Default bounds will preserve the current configured provider and concurrency policy, one content-repair attempt per unit, one bounded protocol-recovery attempt per stage, and a job-level call/time budget. Exact defaults must be exercised on the frozen corpus before cutover. No hidden multiplicative retry ladder: client-internal retries are identified separately from service calls where telemetry permits, and unknown transport usage stays unknown.

Efficiency comes from skipping admitted units, retaining candidates for review-only recovery, deduplicating identical units only within matching context/scope, sharing one queue, and reusing accepted artifacts. Measure call counts, translated/reviewed characters, queue time, stage latency, checkpoint reuse and incomplete coverage. Do not invent token/cost numbers when the client supplies no usage.

## 6. Unified API and frontend state

Expose a single versioned job contract through a dedicated API module; existing resource endpoints become thin adapters during migration and retain their required response envelopes until their consumers move. Proposed operations are POST start-or-resume with an idempotent identity, GET job/status/result, POST retry-pending, POST explicit refresh, and POST stop. Every lookup goes through the resource's existing access/scope checks; opaque job IDs are not authorization.

Separate execution state from content availability:

- Execution: queued, running, waiting_provider, interrupted, failed, cancelled, completed.
- Content: source_only, partial, available, stale.
- Phase: translating, validating, reviewing, repairing, publishing when applicable.

Return source/job/generation identities and a monotonic job revision, required/accepted/pending-translation/pending-review/failed/disclosed-source counts, body/display coverage, safe issues with affected unit labels, retry-after and authoritative allowed actions. Derive counters from the frozen units: required = accepted + pending_translation + pending_review + failed + disclosed_source_fallback; reused is a subset of accepted and immutable preserved fields are counted separately. Client observation state (checking/observing/disconnected/paused) is separate from server execution. A complete body and incomplete dashboard are represented separately; repairing a dashboard cannot force body regeneration.

Add one useTranslationJob composable plus a small shared status/action component. Every current tab consumes it. It reconnects on mount; polls active jobs with bounded backoff; treats a failed HTTP read as local connection uncertainty; allows Check status/Resume after disconnection; cancels request subscriptions and timers on unmount without implicitly cancelling a shared backend job. Responses are admitted only for the current resource/source/language/view generation. Switching to English does not delete progress or accepted Mandarin.

Graph and simulation inventories page through the full eligible source snapshot with a stable cursor. A large graph's pending tail stays visible and makes progress. All component rendering resolves translations by both field identity and current source digest. The after-action record inherits the same Simulation control; no standalone translation button is added for every subcomponent.

## 7. Publication and PDF

Write each admitted artifact into an immutable generation directory alongside its report/handoff or appropriate overlay store. A manifest binds Markdown, structured display, citations, source identities, review-policy identity and their hashes. Stage and validate all files before atomically switching a small current-generation pointer. Readers resolve the pointer once and verify that generation; a replacement never exposes a mixed body/audit/citation set. Keep original canonical files and historical accepted sidecars untouched. Publication, cancellation and generation replacement share a per-artifact lock and documented lock order; a database fence alone cannot protect an external filesystem rename.

SQLite and the filesystem cannot share one atomic commit. Use an explicit publication intent and deterministic generation identity: write staged generation, fsync and validate, atomically publish the pointer under the artifact lock/fence/source check, then record database completion. Restart can reconcile a matching published pointer to its intent, or ignore an unreferenced staged generation. Do not overwrite a newer publication during reconciliation. Acceptance covers process crashes and clean restart; machine power-loss durability is not claimed without separate filesystem/directory-fsync validation.

The TranslationArtifactResolver returns an admitted immutable snapshot with language, source/generation hashes, Markdown, citation map and figure dependencies. Both report views and PDF export consume it. A PDF manifest additionally binds renderer/font/template versions and the resulting PDF hash. Render to a unique temporary destination, validate text/CJK and structure, recheck source admission, and atomically publish the cache entry. Serialize identical exports; failure preserves prior output but does not serve it for mismatched inputs.

The visible button identifies the export language: Mandarin when viewing the accepted Mandarin report, English when viewing English. A Chinese primary is handled as a primary, not as a missing translation variant. The export request carries the displayed artifact identity. If the canonical source or selected publication changes before delivery, return a typed409 stale-artifact response and offer retry. A browser selection change discards the pending response. Downloads never launch translation and never silently substitute a different language. Both report views share busy/error handling and actual PDF-byte validation.

## 8. Compatibility and removal

Implement the new service beside the current interfaces, then migrate every producer and reader before retiring duplicated lifecycle code. This is a staged cutover to one architecture, not a permanent second translation engine.

- Import only existing v1 section/field receipts that validate against their exact current source/target/context/language. A missing complete-document review cannot be relabelled complete, but its individually valid sections can seed a pending v2 job.
- Existing accepted legacy variants remain readable under their historical publication contract. They are not silently upgraded into v2 receipts or regenerated during a read.
- Use explicit adapter readers for old artifact paths. New generation output and compatibility metadata point to one authority; no independent write path remains in ReportAgent or route-level workers.
- Migrate forecast/dossier bodies and structured fields first, then graph/simulation including the record view, then shared UI/export. Preserve public/API consumers throughout and remove unused generation paths after reference search and tests establish they are no longer called.
- Source or validation-policy changes invalidate reuse explicitly. Candidate reuse across reviewer-policy changes requires a new review; source changes require re-extraction and appropriate translation work.

## 9. Acceptance and stopping condition

| Scenario | Required result |
|---|---|
| Exact reported22-section failures |20/22 or21/22 valid sections import; ordinary resume submits only pending sections; full reviewed output passes existing source/citation/publication checks |
| Reviewer response malformed or missing one result | Persisted candidate remains; no translation call for accepted or review-only units; missing verdict never accepted |
| Worker crash at each stage | Restart retains durable candidate/receipts; old worker cannot commit; remote unknown attempt is recorded |
| Concurrent/duplicate start and refresh, including two backend processes | One job per matching identity; bounded single owner; refresh failure preserves accepted generation |
| Source/view/language changes | Stale job responses cannot publish or overwrite the selected view; private actor content never enters a public cache/result |
| Large graph or simulation inventory | Full coverage denominator; bounded batches advance pending tails; no silent cutoff |
| Every tab/control | Mount, start, progress, partial/failure, retry, disconnect/reconnect, language switch and unmount share the same contract |
| Actual English/Mandarin PDFs | Correct admitted language and filename; Chinese glyphs, tables, figures, citations and pagination pass text and rendered-page inspection |
| Coordination database unavailable | New work fails explicitly; independently validated published content stays readable; no competing legacy worker starts |
| Existing accepted artifacts | Before/after source and accepted-byte hashes match unless an explicitly successful refresh replaces a variant |
| Efficiency | No provider calls for unchanged accepted results; no translation calls for review-only retry; only1 or2 missing sections translated in the reported fixtures; exact call counts documented |

Use the existing guarded backend runner and provisioned dependencies, compiled Vue consumer tests, full frontend suite/build, real PDF fixtures, and independent review of exact tested bytes. Bounded live translation recovery is a separate final observation using the existing configured provider after current worker ownership is known. No new research pipeline is needed. Record failures honestly; external provider availability cannot be guaranteed by source tests.

## 10. Independent design review

Two read-only specialist reviews support the contract and migration. The frontend review requires a separate client-observation state, monotonic revision admission, explicit counter invariants, and coverage of the default completed simulation record. The backend/PDF review favors SQLite over expanding JSON files into a transactional journal, but requires an elected OS-lock owner, conditional fenced writes, publication locks shared with cancellation, explicit database/filesystem crash reconciliation, and preserved readable publications during coordination-store failure. These requirements are incorporated above. The chosen export-race behavior is typed409 and retry rather than silent replacement. No source or live execution acceptance is implied by this design review.
