# Translation hardening and language-aware PDF export

**Date:** 2026-10-26 (Asia/Shanghai)
**Status:** Superseded by the user on2026-10-26: redesign the translation system instead of applying individual patches. Retained as diagnostic history, not the active implementation plan.
**Continuity:** [handoff.md](handoff.md).

## Objective
Make every existing translation control complete its supported start/read/poll/retry workflow reliably, preserve truthful incomplete/error states when a provider cannot finish, and make both report views export the currently displayed, admitted language. Mandarin export uses an already accepted Mandarin artifact. English export uses the English artifact. Downloading must not launch translation or silently return another language.

## Implementation slices and checks

### 1. Make translation and review recovery stage-aware
Keep separate bounded states for translation, parsed-structure validation, semantic review, and repair. Preserve a structurally valid candidate when only its review response needs correction. Retain independently validated entries when another entry is missing or malformed; never accept a missing, duplicate, foreign, ambiguous, or negative verdict. Allow only explicitly harmless envelope presentation variations, with exact identity and required-field checks; do not guess renamed keys or interpret source content as instructions. Keep at most one content repair per entry and an explicit total provider-call budget. Provider outage, refusal, malformed response, incomplete review, structural difference and genuine semantic rejection receive stable safe codes and readable messages. Persist stage, entry key, attempt/count and hashes without raw provider bodies or credentials.

Checks: positive valid and harmless-envelope cases; duplicate/unknown/missing entries; malformed or truncated JSON; malformed/missing review; altered facts/negation/units/links/citations; provider timeout/quota/refusal; budget exhaustion. A review-only protocol failure must not call translation again for the retained candidate. A genuinely rejected translation must still fail unless a bounded repaired candidate passes a fresh review.

### 2. Resume only missing or invalid sections
Add a source/language/engine/context-bound recovery carrier for long-form dossier/report work, using existing persisted audits where safe. Validate each stored section receipt and current source before reuse. Persist progress atomically and keep attempted artifacts separate from the accepted publication. Ordinary Retry repairs pending entries; explicit full refresh remains a separate user action. Restart, source change, corrupted proof and failed replacement must neither publish unreviewed text nor remove a previously accepted translation. Apply the same bounded progress principle to structured display and simulation overlays through the existing shared service.

Checks: real manager/API retry of a22-section fixture with one or two missing reviews; assert accepted sections are never resent and source files remain unchanged. Exercise restart, failed write, tamper, source change, wrong language/context/engine, and concurrent request controls. Replay the shape and relevant content of the exact saved failure sections in isolated fixtures. Saved production reports remain unchanged during offline tests.

### 3. Close every translation UI state transition
Use [findings.md](findings.md) as the control matrix. Repair graph failure/partial retry, graph identity/revision races and coverage limits; forecast polling on mount and transient read errors; and the omitted world-state provenance string. Cover the existing dossier, forecast, graph, persona/feed, OASIS world-state and World-v1 controls. There is no standalone ontology translation control. The after-action simulation record has no control today and remains a separately documented scope gap, rather than adding another independent feature. Reuse the shared controller where appropriate. Cover queued/generating/partial/failed/interrupted/available states; start, polling, retry and language switching; switching report/period/tab during an outstanding request; and unmount cleanup. A UI retry must reach the intended backend operation once and continue polling while work remains. Keep explicit source fallback and incomplete notices. Propagate useful safe error details without making cache corruption a500 or leaving a loading state stuck.

Checks: actual compiled Vue components and API handlers using controlled transports, with a per-control acceptance matrix. Verify only visible permitted simulation text is submitted and that already translated entries do not starve pending tails. Run relevant component tests, the full frontend suite and a production Vite build after changes.

### 4. Finish language-aware PDF export
Use the existing PDF renderers and backend endpoints. Correct the dossier route to render the verified Markdown snapshot and recheck its source/audit identity before delivery. Add per-language serialization, atomic replacement and dependency-bound reuse rather than deleting the shared output before rebuilding. Reuse the stronger forecast-export patterns. Give both Research Report and Forecast Report an obvious PDF action with an explicit language label matching the displayed artifact. Correct busy/error behavior and derive the download filename from the artifact language. Mandarin requires an admitted Mandarin body; English remains available from the source view. Revalidate source/translation identity at export time and invalidate stale cached PDFs when their dependencies change. Verify Chinese glyphs, headings, tables, citations, figures and page layout using real generated files.

Checks: actual English and Mandarin download routes; stale/missing/rejected translations; source/translation switching during export; renderer unavailable and backend failure responses; source-bound PDF caching; Chinese text extraction plus rasterized-page inspection. No download should silently produce English while labelled Mandarin, or trigger paid translation.
