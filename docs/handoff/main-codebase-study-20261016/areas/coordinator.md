## Active coordinator

`PipelineOrchestrator` coordinates six stages by direct Python service calls. Research and OASIS execute in subprocesses; the web request starts a daemon thread and returns IDs immediately. The identity chain is pipeline → project → graph → simulation → report. `PipelineState` persists those IDs, options, stages, artifact pointers, process ownership and heartbeats. `TaskManager` supplies a polling task, while the durable pipeline JSON survives backend restarts. The initial progress bands are research 0–30, ontology 30–40, graph 40–60, prepare 60–72, run 72–92 and report 92–100. Research-only uses 0–100 for research. `_recompute_dynamic_bands` can adjust later bands using actual work estimates; percentages are presentation state, not delivery evidence. ## Research subprocess and engine selection

`resolve_research_engine` normalizes unset/unknown values to v3; `linear` is an alias for v3 and `legacy`, `deerflow`, `agentic` select legacy. A saved actor policy requiring the sealed actor plane selects legacy. New v3 admissions set that requirement false and record the unsupported-plane reason, because v3 emits unsealed report-grounded actor rows. Provider/model concurrency, inner subagents and outer workers share a bounded envelope; these are separate layers of concurrency.
