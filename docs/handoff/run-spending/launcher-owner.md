## CLI and descriptor contract

Invoke the launcher with verified Python and `-I -S -B`. Commands are `prepare --source S --deerflow-source D --root R --spec SPEC`, `verify --root R`, and `run --root R --authorization APPROVED_MANIFEST --registry ARCHIVE --credentials PRIVATE_JSON`. Preparation uses the reviewed checkout script; `run` MUST execute `R/app/backend/scripts/target_acceptance_run.py` itself. Preparation copies only explicitly hash-reviewed regular source files to a new private R, verifies provisioned dependency files read-only, and writes request/config/runtime receipts. It creates no authorization or ledger. The later run action validates a separately approved manifest and consumes authorization through the core outside-R registry. Missing existing state is never recreated.

`R/spend/runtime.json` includes `python` (canonical verified regular executable path), its hash, source file hashes, dependency paths and file hashes, request/config hashes, exact import roots, and mutable roots. The frozen core disallows spend/ entries in source_files, so the manifest pins `R/control/runtime.json`, an immutable byte-identical mirror of `R/spend/runtime.json`, plus `R/control/request.json`, `R/control/config.json` and all application/harness files. Every verification requires both runtime descriptors to match exactly. Preparation outputs the hash map needed for review, not an authorization.

Coordinator child command: `[python, '-I', '-S', '-B', R/app/backend/scripts/target_acceptance_run.py, '_child', '--', original_script, *args]`. The child validates all required environment carriers, including the operation carrier for registered participants, and matching core/module/source/runtime hashes before adding reviewed import paths. It then activates the registered participant and operation before `runpy.run_path` executes the script with sanitized argv. No `.pth` processing or `site.addsitedir` is used.

The parent holds `core.run_lock(binding)` across common start, the complete background pipeline lifetime, and terminal verification. Common start owns immutable pipeline binding. This launcher does not automatically resume or provide a resume command. `_child` returns the fixed `resume_denied` code for `--resume` or any existing handoff/v3 directory, including unflagged automatic reuse. The coordinator may separately admit explicit clean resume only after receipt-valid completed research has sealed case/evidence/estimators; unfinished research must be denied before generation advance. No legacy checkpoint identifier is invented and no cap renewal is implemented.

## Decisions and remaining work

The preparation spec has exact keys `schema="target-acceptance-prepare/v1"`, `python`, `python_sha256`, `app_files`, `deerflow_files`, `dependencies`, `request`, and `model`. Source file maps contain relative path to SHA-256 pairs; dependency entries have exactly `path` and a complete `files` map. Dependency directories with `.pth`, editable links, or application/harness packages are refused. Source copying excludes uploads, environment files, credentials, Git metadata, virtual environments and bytecode. `deerflow_files` supplies reviewed harness source (including `backend/packages/harness/deerflow` and its config package); reviewed `app_files` bridge Python files are copied identically into the private child tree. Existing `config.yaml` files are excluded because the launcher generates the single-model config. Python imports compile the freshly verified source bytes and never execute dependency bytecode caches. One empty regular `deer-flow/skills/.drf-runtime-skill-sync.lock` is allowed as a runtime artifact; the skills tree itself remains fully hash-pinned. Coordinator may instead provide read-only skill verification.

The exact model fields are `provider`, `alias`, `name`, `endpoint`, `input_ceiling`, and `max_output_tokens`. `request.model` is the existing research alias, for example `glm`; `name` is the served API model, for example `glm-5.3`. The child model config has `models[0].name=alias` and `models[0].model=name`. Parent provider/base/fast/strong fields use the explicit provider and served name, with tiering disabled. Known provider/alias pairs come from existing Config/research mappings (glm, deepseek, qwen, minimax, kimi); unknown pairs refuse. This does not establish external billing qualification. The corresponding preflight credential alias, for example `ZHIPUAI_API_KEY`, is derived only from the same explicitly injected `LLM_API_KEY`; it cannot select another account. Credential files accept only `LLM_API_KEY` and `FIRECRAWL_API_KEY`.

Prompt input must be the exact normalized approved UTF-8 text. Internal LF newlines and Unicode are supported. CR characters, including CRLF line endings, are unsupported and rejected by check_request/prepare before authorization; the existing research CLI's universal-newline read would otherwise change those bytes. The launcher never strips, replaces invalid UTF-8, normalizes Unicode/newlines, or rewrites a wrong prompt file to pass validation. The later engine guard compares the actual loaded question and CLI scope to fixed R/control/request.json through the immutable core request hash, preventing a changed file between bootstrap and the CLI read from reaching model construction.

Reuse the existing source-before-import and replay audit-hook discipline, without changing its network protections. Preserve HOME, home, CODEX_HOME and USERPROFILE. Reject ambient credential routes and dotenv files before app import; inject only explicitly approved credential fields during the future run action. Read-only reusable dependencies must have a complete hash inventory and cannot provide editable application origins. This is a trusted local-process boundary, not an operating-system sandbox or verified billing guarantee.
