## 1. Position in the workflow and actual entrypoints

The module connects research, ontology, graph, preparation, simulation, and reporting through service calls and durable IDs. Its initial six progress bands are research 0–30, ontology 30–40, graph 40–60, prepare 60–72, run 72–92, and report 92–100; `research_only` allocates 0–100 to research. These are progress bands, not six independent persisted jobs. `PipelineState` carries the project, graph, simulation, report, task, and handoff references between stages. ## 4. Tool-budget epochs and checkpoint lineage are separate authorities

`_activate_research_budget_epoch` keys an epoch to `state.task_id`, with deterministic `initial-<pipeline_id>` fallback. All lanes and synthesis attempts in that task share a database. Re-entry finds the task's history row and reuses its DB/telemetry/epoch tuple. A new task can allocate another epoch up to `RESEARCH_BUDGET_MAX_EPOCHS` (default 3). The epoch directory is `handoff/research_budget_epochs/epoch-<ordinal>-<sanitized task>`, with `research_budget.sqlite3`; the active telemetry remains at root `handoff/research_budget.json`. Previous root telemetry is copied into the prior epoch's `final_research_budget.json`, or a first legacy archive. Archive failure and epoch-cap exhaustion raise rather than launch. Sources: `backend/app/services/pipeline_orchestrator.py:1801`, `backend/app/services/pipeline_orchestrator.py:1815`.

The new epoch row stores ordinal, epoch/task IDs, epoch directory, DB path, telemetry path, and creation time in `options.research_budget_epochs` and `options.research_budget_epoch`. The initial JSON snapshot records run/epoch, limits, empty global/lane counts, and budget-enabled metadata; an old root DB is retained via an option pointer. That snapshot and pipeline state are persisted before returning. Defaults here are attempts 1800, search global/lane 900/360, and fetch global/lane 450/180. Source: `backend/app/services/pipeline_orchestrator.py:1881`.

`_research_budget_exhaustion` reads the telemetry snapshot and ignores an unexpected epoch. It checks positive global attempts, network-search, and network-fetch caps against their counters in that order; missing/unreadable/non-object snapshots return no saturation result. The function's own contract identifies SQLite as the admission authority and this JSON as a pre-spawn check. The actual SQLite admission implementation lies across the research boundary. ## 9. Run manifest and stage fingerprints

`_build_run_manifest` creates schema/pipeline/mode/created/updated fields, best-effort repository SHA and DeerFlow reference, resolved research model/depth/depth-budget timeout/language/actor policy, placeholder ontology/graph/report model pairs, simulation limits/round placeholders and switches, graph embedding/reranker identity, Python version, and `redacted_flag=True`. It optionally adds installed key-package versions via `importlib.metadata`; it does not run a package-freeze/install operation. Calendar generation mode records only an explicit max-rounds option; the other mode can use the configured default. Sources: `backend/app/services/pipeline_orchestrator.py:7243`, `backend/app/services/pipeline_orchestrator.py:7258`, `backend/app/services/pipeline_orchestrator.py:7276`, `backend/app/services/pipeline_orchestrator.py:7296`, `backend/app/services/pipeline_orchestrator.py:7306`.

Repository and DeerFlow revision helpers run bounded `git rev-parse HEAD` at application runtime and degrade to `None`/`vendored` as implemented. The manifest skeleton's research timeout is computed by its depth-budget helper/fallback; the runner's launch-time timeout precedence is the separate code path described above. The run manifest is a snapshot of the fields it constructs, rather than a copy of the entire environment or options dictionary. Sources: `backend/app/services/pipeline_orchestrator.py:7243`, `backend/app/services/pipeline_orchestrator.py:7258`, `backend/app/services/pipeline_orchestrator.py:7312`, `backend/app/services/pipeline_orchestrator.py:2271`.

`_run` writes a new first-version manifest on entry, including resume entry. `_write_run_manifest` is gated by `RECORD_RUN_MANIFEST`, recursively redacts it, writes it atomically, and adds the `run_manifest` artifact pointer. `_update_manifest` loads or reconstructs it, replaces ontology/graph/report resolved model pairs from current configuration, optionally adds actual total rounds and temporal calendar unit/round count/horizon, refreshes time, redacts and writes. Ordinary failures only log debug messages. Stage callers were inspected at ontology, graph, report and simulation progress. Sources: `backend/app/services/pipeline_orchestrator.py:11895`, `backend/app/services/pipeline_orchestrator.py:10374`, `backend/app/services/pipeline_orchestrator.py:10393`, `backend/app/services/pipeline_orchestrator.py:12309`, `backend/app/services/pipeline_orchestrator.py:12391`, `backend/app/services/pipeline_orchestrator.py:13041`, `backend/app/services/pipeline_orchestrator.py:13187`.

`redact_secrets` returns a new recursively transformed structure. Sensitive field names replace entire values; obvious secret-token patterns in strings are also replaced; list/tuple inputs become lists. The manifest's non-sensitive observation field names (`redacted_flag`, `package_versions`) are deliberately chosen to survive that field-name matching. Source: `backend/app/utils/security.py:20`, `backend/app/utils/security.py:35`, `backend/app/services/pipeline_orchestrator.py:7370`.

`_stage_walls` derives stage durations only when both timestamps parse and their difference is nonnegative. It also adds the separately stored `options.ensemble_wall` interval when valid. The final telemetry path passes that duration map into `build_stage_telemetry`, writes pipeline `telemetry.json`, and exposes a compact rollup under options; the helper itself does not infer missing timing endpoints. Sources: `backend/app/services/pipeline_orchestrator.py:3811`, `backend/app/services/pipeline_orchestrator.py:13440`.
