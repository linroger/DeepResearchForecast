## Runtime and adapter findings

`graphiti_client.Zep` is the app-local facade, not a `zep_cloud` import. Its `api_key` parameter is accepted for compatibility, and its graph namespace delegates to the singleton runtime (`backend/app/services/graphiti_client/client.py:349`). Node wrappers expose both `uuid_` and `uuid`; edge wrappers include fact/name, endpoint UUIDs, attributes, ISO temporal fields, and both `episodes` and `episode_ids` (`backend/app/services/graphiti_client/client.py:35`, `backend/app/services/graphiti_client/client.py:49`). Episode handles report processed immediately because ingestion is synchronous (`backend/app/services/graphiti_client/client.py:73`). `EpisodeData` carries `data`, `type`, and optional `reference_time`; ontology compatibility classes are Pydantic models with extra fields ignored and `EntityText=str` (`backend/app/services/graphiti_client/compat.py:16`, `backend/app/services/graphiti_client/ontology.py:22`).

`GraphitiRuntime` owns a background asyncio loop, caches Graphiti objects and ontologies by graph ID, and uses one write lock per graph (`backend/app/services/graphiti_client/runtime.py:184`, `backend/app/services/graphiti_client/runtime.py:249`). Sync `run` cancels a timed-out coroutine before raising; the default timeout is read from `Config.GRAPHITI_OP_TIMEOUT_S` (`backend/app/services/graphiti_client/runtime.py:128`, `backend/app/services/graphiti_client/runtime.py:224`). `GRAPH_SERIALIZE_READS` optionally takes that same lock for reads. `GRAPH_BACKEND=auto` selects explicit `FALKORDB_HOST`, then available `falkordblite`, then Kuzu; this is selection by configuration/import availability rather than a runtime connection-failure cascade (`backend/app/services/graphiti_client/runtime.py:283`). Graph ID is the tenant database and group ID. Embedded storage uses `GRAPHITI_DATA_DIR/falkor.db`; Kuzu uses `GRAPHITI_DATA_DIR/kuzu/<graph_id>` (`backend/app/services/graphiti_client/runtime.py:316`). Falkor driver/session wrappers JSON-encode nested property values at both query surfaces (`backend/app/services/graphiti_client/falkor_driver.py:33`, `backend/app/services/graphiti_client/falkor_driver.py:72`).

Ontology registration stores entity/edge model classes and a `(source type,target type) -> [edge names]` map in memory (`backend/app/services/graphiti_client/runtime.py:442`). Prose ingestion runs `Graphiti.add_episode` with the registered ontology and reference time (`backend/app/services/graphiti_client/runtime.py:760`). `_add_episode_locked` bounds complete extraction attempts with `GRAPH_CHUNK_MAX_ATTEMPTS`, retries schema echo/validation/parse failures, and can temporarily swap to `LLM_FALLBACK_PROVIDER` through the separately configured model/base URL/key names (`backend/app/services/graphiti_client/runtime.py:593`, `backend/app/services/graphiti_client/runtime.py:666`). Concurrent batches hold the graph lock around fan-out, retain successful UUID order, and replay eligible rate-limit failures once serially after a bounded cooldown; the replay shares the chunk attempt budget (`backend/app/services/graphiti_client/runtime.py:1071`). This lock prevents external overlap; intra-batch extraction is still concurrent, as the source explicitly documents.

The app LLM adapter uses a dedicated `GRAPH_LLM_EXECUTOR_WORKERS` pool and copies ContextVars for telemetry attribution. Graphiti small/medium requests route to the app's fast tier; large requests use strong. Two temperatures, 0.0 and 0.4, provide schema-envelope salvage or corrective schema validation before returning data; parse failures map to Graphiti `EmptyResponseError`, transient SDK failures to `RateLimitError` (`backend/app/services/graphiti_client/llm_adapter.py:59`, `backend/app/services/graphiti_client/llm_adapter.py:114`). This study does not execute those provider paths.

Embeddings use a lazily loaded local SentenceTransformer, configured by `GRAPHITI_EMBED_MODEL` and `GRAPHITI_EMBED_DIM`; the package exports `EMBEDDING_DIM` before importing Graphiti (`backend/app/services/graphiti_client/__init__.py:17`, `backend/app/services/graphiti_client/embedder.py:43`, `backend/app/services/graphiti_client/embedder.py:226`). `EMBED_EXECUTOR_WORKERS` isolates encoding, with best-effort `OMP_NUM_THREADS`/torch pinning. The 50,000-entry memory LRU and optional SQLite cache at `EMBED_DISK_CACHE_PATH` key vectors by model plus whitespace-normalized text hash. Disk errors disable the disk layer; missing vectors are encoded once per unique key (`backend/app/services/graphiti_client/embedder.py:120`, `backend/app/services/graphiti_client/embedder.py:284`). RRF/MMR/node-distance/combined recipes are exposed; node-distance without a center falls back to RRF, and cross-encoder requests degrade to RRF when the installed reranker is `NoOpCrossEncoder`. `GRAPHITI_RERANKER=bge` chooses the alternate real reranker (`backend/app/services/graphiti_client/runtime.py:358`, `backend/app/services/graphiti_client/runtime.py:1448`, `backend/app/services/graphiti_client/runtime.py:1647`). JSON search filters translate labels, edge types and bi-temporal dates; malformed specifications degrade to unfiltered retrieval with a warning (`backend/app/services/graphiti_client/runtime.py:1507`).

The runtime lists all ordered entity UUIDs, filters groups in Python, and pages with monotonic cursor offsets; edges are scanned without property predicates and filtered/deduplicated in Python (`backend/app/services/graphiti_client/runtime.py:1717`, `backend/app/services/graphiti_client/runtime.py:1741`, `backend/app/services/graphiti_client/runtime.py:1789`). `actor_graph_seed_state` deliberately retains duplicate physical edge UUIDs and selects only `actor-graph-seed/v1` rows for manifest validation (`backend/app/services/graphiti_client/runtime.py:1931`). Community construction/listing and directed `causal_paths`/undirected `n_hop_subgraph` are additional retrieval surfaces (`backend/app/services/graphiti_client/runtime.py:1209`, `backend/app/services/graphiti_client/runtime.py:1294`, `backend/app/services/graphiti_client/runtime.py:1383`). Paths carry per-edge sign, strength, polarity, lag and fact, parsed from folded fact text; lag accumulation uses numeric magnitudes without unit conversion.

Deterministic triplets require all three UUIDs and complete delimited model records. They embed those records and save canonical node/edge objects directly, bypassing LLM identity resolution (`backend/app/services/graphiti_client/runtime.py:907`). Ordinary triplets use Graphiti's deduplication path (`backend/app/services/graphiti_client/runtime.py:866`). Merge execution protects entity-type seeds and canonical actor seeds, permits alias seeds to merge only into the same actor ID, retains seeded edge UUIDs/attributes, and refuses a relationship collapse to a self-loop. A failed seed-edge rewire prevents victim deletion; extracted edges receive fresh UUIDs. Victim episodic mentions are not rewired (`backend/app/services/graphiti_client/runtime.py:2020`).

## Ontology and bounded graph input

`OntologyGenerator.generate` consumes document strings, simulation requirement, optional extra context/template/question/actors and returns `entity_types`, `edge_types`, and `analysis_summary` (`backend/app/services/ontology_generator.py:539`). The social template requests ten types with Person/Organization fallbacks; the general template requests six to ten domain types and conditional fallbacks. Explicit template wins; configuration follows; unknown templates select social. `ONTOLOGY_AUTO_SELECT` can classify the question using bilingual public-opinion keywords (`backend/app/services/ontology_generator.py:483`, `backend/app/services/ontology_generator.py:565`). The effective prompt optionally appends rich entity/edge metadata plus cast discipline (`backend/app/services/ontology_generator.py:509`). Research strings are sanitized independently and delimited; the document budget is 120,000 characters with head/middle/tail sampling (`backend/app/services/ontology_generator.py:640`, `backend/app/services/ontology_generator.py:692`).

Postprocessing coerces top-level collection fields, drops malformed/duplicate/unnamed entity types, truncates descriptions to 100 characters, rewrites reserved attribute names to `entity_<name>`, and accepts `relation_types` as an edge alias when rich schema is enabled. Missing archetypes and edge family/valence are inferred; five causal edge names explicitly force causal/directional semantics. Type budgets cap at ten each and edge endpoints are reconciled against the final type names (`backend/app/services/ontology_generator.py:948`, `backend/app/services/ontology_generator.py:1148`). General-template empty entity output gets one social-template generation fallback. Conditional fallback inference treats missing or unusable actors as requiring both legacy fallback types (`backend/app/services/ontology_generator.py:612`, `backend/app/services/ontology_generator.py:830`).

`render_compact_actor_dossier` returns bounded Markdown and telemetry from canonical actors, sorted by simulation tier, salience and normalized name. It renders at most 20 actors, 80 relationships touching the selected cast and 40 outside one-hop neighbors by its call defaults, plus situation brief, incentives, selected intelligence dimensions/gaps, events and topics. Unrelated relationships are excluded. It stops at whole-line boundaries for its 80,000-character default budget (`backend/app/services/actor_dossier_compactor.py:151`). Telemetry records selected counts and final truncation; an invalid or empty actor input returns an empty string with a fallback reason.

## Resolution, pruning, and graph entity reads

`resolve_entities` reads graph nodes, embeds names, plans merges and executes each independently; callers receive clusters and execution audit records (`backend/app/services/zep_entity_resolver.py:480`). `plan_merges` uses normalized exact/containment names, node aliases and authoritative actors.json aliases; typed labels must be compatible, and distinct canonical names cannot be merged. Missing embeddings require exact signals. The full planner lets an authoritative dossier alias bypass low cosine; the large-graph `plan_merges_fast` uses exact-name/alias buckets and still applies its cosine gate. `GRAPH_RESOLVE_MAX_NODES` chooses between planners (`backend/app/services/zep_entity_resolver.py:200`, `backend/app/services/zep_entity_resolver.py:352`). Canonical seed nodes outrank ordinary nodes; type seeds are excluded and actor seeds cannot directly merge with each other (`backend/app/services/zep_entity_resolver.py:39`, `backend/app/services/zep_entity_resolver.py:441`).

`plan_prune` keeps all actor canonical/alias matches and fills available capacity only from the configured N-hop neighborhood, ordered by distance, mention-plus-degree importance, name and UUID. The effective hard cap rises to the number of core nodes. The per-type cap affects additions; the legacy `min_degree` is retained in the signature/audit but does not exempt nodes (`backend/app/services/graph_pruner.py:94`). `prune_graph` skips destructive work when disabled, when no core matches, or when actor-row coverage is below `GRAPH_PRUNE_MIN_CORE_COVERAGE`. It records planned versus actual counts, rereads survivors, retries only remaining members of the original deletion plan once, and verifies exact survivor set, core survival and capacity. Failed post-read yields unknown actual counts and a degraded audit; layout is a separate optional enhancement (`backend/app/services/graph_pruner.py:244`).

`ZepEntityReader.filter_defined_entities` returns `FilteredEntities` with `EntityNode` rows and optional adjacency context. It requires a custom label beyond Entity/Node and optionally a configured type match. Classification precedence is node attributes, matched actor row, then ontology type metadata if `SIM_TIER_FROM_ONTOLOGY` is enabled. With `SIM_TIER_ELIGIBILITY`, explicit ineligible archetype/tier data excludes rows; no explicit signal preserves legacy admission. Media classification on an actor row also supplies a signal when exclusion is enabled (`backend/app/services/zep_entity_reader.py:34`, `backend/app/services/zep_entity_reader.py:319`). Edges are indexed once by endpoint; context preserves incoming/outgoing direction and neighbor names/summaries (`backend/app/services/zep_entity_reader.py:377`).

## Actor utilities and identity semantics

Only then does it consider containment with at least four characters on both sides, choose the longest surface, and reject ties across distinct canonical names (`backend/app/utils/actors.py:145`, `backend/app/utils/actors.py:445`). This is a lookup contract; the graph resolver uses its separately documented clustering rules.

`actor_intelligence_payload` accepts supported v1 and unversioned migration dictionaries, but rejects explicit unknown versions. `actor_intelligence_dimension` accepts direct canonical values, `claims/items/entries` wrappers, and pre-v1 flat aliases. Claim renderers retain bounded date/confidence/evidence/status/horizon/conditions/amount/unit/source information. Presence/coverage helpers measure structural content, not truth (`backend/app/utils/actors.py:190`, `backend/app/utils/actors.py:272`, `backend/app/utils/actors.py:350`, `backend/app/utils/actors.py:1951`). `actor_briefing`, `actors_digest`, `behavioral_dna_block`, `roster_block` and `situation_brief` render bounded context for legacy profile/config/report consumers (`backend/app/utils/actors.py:508`, `backend/app/utils/actors.py:598`, `backend/app/utils/actors.py:1151`, `backend/app/utils/actors.py:1191`, `backend/app/utils/actors.py:1323`). They do not themselves enforce the full producer receipt admission contract.

Eligibility is implemented by tier. Explicit tier wins; otherwise source archetypes and recognized media become tier 3, other non-actor/non-collective archetypes become tier 4, high-influence actors become tier 1 and known lower influence tier 2. Missing influence defaults to tier 1. `is_agent_eligible` accepts tiers 1 or 2; it does not separately reject an explicit tier-1 row based on its archetype. `is_media_entity` honors explicit tier 1/2 as an actor exception (`backend/app/utils/actors.py:862`, `backend/app/utils/actors.py:907`, `backend/app/utils/actors.py:928`, `backend/app/utils/actors.py:961`). `salience_score` prefers bounded explicit score/tier then influence fallback (`backend/app/utils/actors.py:970`).

Relationship utilities filter endpoints through canonical/alias name sets, retain direction, map type to valence/polarity, project ten named roster buckets, and derive initial follow pairs by type. Allies follow the higher-influence endpoint in the legacy helper; opponents/competitors/partners monitor both ways; dependency, regulation, investment and supply each use their defined direction (`backend/app/utils/actors.py:737`, `backend/app/utils/actors.py:1003`, `backend/app/utils/actors.py:1077`, `backend/app/utils/actors.py:1270`). Source indexes support either tier-letter tags or fixed original-position `[S<n>]` tags; the unified index ranks research-cited sources then tier, and restores original numeric order after selection (`backend/app/utils/actors.py:1585`, `backend/app/utils/actors.py:1713`).

`reconcile_cast` groups duplicate actor rows by name/alias overlap or long-name containment, picks the richer row, unions aliases, fills missing fields, audits scalar conflicts and merges intelligence claims without discarding variants. It preserves producer coverage/provenance snapshots and rewrites victim-name relationship endpoints (`backend/app/utils/actors.py:2094`, `backend/app/utils/actors.py:2201`, `backend/app/utils/actors.py:2333`). `ontology_from_actors` and `ontology_seed_block` project type/relationship hints for ontology generation; adaptive budget permits enough new types to approach eight while preserving the ten-type hard maximum (`backend/app/utils/actors.py:2451`). The main orchestrator treats a sealed v1 roster as immutable, so helper capability must not be confused with post-seal mutation authority (`backend/app/services/pipeline_orchestrator.py:12185`).

Events have proportional-round and exact-calendar mappings. Proportional scheduling optionally reserves a reaction buffer; calendar scheduling excludes dates on/before as-of and retains beyond-horizon rows separately (`backend/app/utils/actors.py:1398`, `backend/app/utils/actors.py:1463`). Forecast helpers parse probability bands, validate one-to-six unique scenarios whose probabilities sum within 0.02 of one, seed WorldState with scenario/base-rate fallbacks, and optionally recover two-to-six scenarios from a report section with a looser 0.9–1.1 midpoint-total gate (`backend/app/utils/actors.py:2515`, `backend/app/utils/actors.py:2555`, `backend/app/utils/actors.py:2613`, `backend/app/utils/actors.py:2765`). `project_relationships` emits explicitly labeled model trajectory priors, not observations (`backend/app/utils/actors.py:2844`).

## Actor context packs and epistemic boundaries

`actor-context/v1` is a deterministic data artifact; `actor-context-manifest/v1` binds selected pack files. The canonical 17 dimensions are identity/history, values/worldview, incentives, motivations, capabilities, constraints, operational preferences, alliances, opponents/competitors, decision rights/process/triggers, current actions, future plans, investments/capital allocation, track record, likely actions, red lines and knowledge state (`backend/app/services/actor_context.py:26`, `backend/app/services/actor_context.py:98`). `actor_id_for` uses explicit actor_id/id, otherwise a normalized-name SHA-256 prefix. Pack filenames use a restricted ID or hashed fallback (`backend/app/services/actor_context.py:447`).

Report relevance scores canonical names/aliases and discriminating actor evidence phrases, excluding common generic terms. It selects at most eight sections under an 8,000-character report budget, at most 3,200 characters per section; long sections use ranked complete paragraphs restored to original order. It records omitted sections and selection reasons (`backend/app/services/actor_context.py:498`, `backend/app/services/actor_context.py:612`, `backend/app/services/actor_context.py:694`). Structured incident relationships, events, contested claims and quantitative facts require source_refs on v1 input and are bounded separately (`backend/app/services/actor_context.py:781`, `backend/app/services/actor_context.py:814`). A v1 shared-context projection omits raw situation-brief/hot-topic prose; it retains question, as-of and horizon metadata (`backend/app/services/actor_context.py:837`).

`_validate_actor_intelligence_contract` rejects unknown versions, nested v1 without the top-level contract, incomplete row coverage, bad hash shapes, a changed/empty exact report, missing/duplicate actor IDs, bad roster/count/dimension metadata and missing generation/coverage data. At this boundary the dossier/source hashes are shape-checked and carried forward, because their original inputs are not independently supplied here (`backend/app/services/actor_context.py:1207`). `build_actor_context_pack` also proves the selected row equals its root-roster row, rejects claims beyond the as-of cutoff, and requires every v1 dimension to have sourced content or an explicit gap plus at least one actor-relevant report section (`backend/app/services/actor_context.py:930`, `backend/app/services/actor_context.py:1299`).

Access and truth are independent. `_epistemic_context` puts analyst inference in modeler-only data regardless of actor_knows. Literal JSON `false` on the row or qualifiers overrides positive access; literal `true`, or an allowlisted actor-known visibility, can grant access. String true/yes is not a grant. Contested/unknown claims can be actor-visible while retaining uncertainty. A claim's placement in `knowledge_state` alone gives no access (`backend/app/services/actor_context.py:953`). The actor-known allowlist is actor_known, known_to_actor, actor_internal, internal_to_actor and private_actor_knowledge; public relationship authority has its separate public/public_record/publicly_known/open_source allowlist and verified_fact/actor_stated_claim evidence gate (`backend/app/services/actor_context.py:29`, `backend/app/services/actor_context.py:415`).

Evidence gaps are typed six-field rows: reason, attempted_queries, receipt_ids, result_ids, attempt_count and exhausted. Bounds are 320 characters per reason/query, 180 per ID, two queries, eight IDs per receipt/result list, two rows per dimension and 34 total; attempts cap at one million. Canonical structured gaps must normalize losslessly and contain exactly those six fields. Legacy strings upgrade to zero attempts and exhausted=false. Canonical audit query/ID bytes are preserved within bounds; display labels are sanitized independently (`backend/app/services/actor_context.py:47`, `backend/app/services/actor_context.py:160`, `backend/app/services/actor_context.py:241`). These gaps remain modeler audit data, never actor information access.

The default bounded context is 16,000 characters with a 2,000 minimum. Identity and epistemic policy are required; optional shared/report/structured blocks are accepted whole when they fit. Claims and gap dimensions are never blindly sliced into partial JSON (`backend/app/services/actor_context.py:1049`, `backend/app/services/actor_context.py:1136`). Pack artifacts include source hashes, full intelligence/epistemic data, selected sections/rows, coverage, bounded text and omission audits. The builder atomically writes `actor_context/<id>.json`, hashes the actual bytes, reloads deep-decoded objects, then writes `actor_context_manifest.json`. Validation checks actual manifest/pack bytes, relative paths, count/roster, schema, identity, source bindings and bounds (`backend/app/services/actor_context.py:1426`, `backend/app/services/actor_context.py:1501`). The full pack is audit/calibration data; it is not copied wholesale into every persona.

## Role compilation and simulation persona boundaries

`build_actor_role_contract` deterministically creates `actor-role/v2` from one actor, its dossier and matching context pack. Unknown explicit intelligence versions return no role. It is a behavioral calibration contract with epistemic labels; not every field in that contract is asserted actor knowledge.

Canonical hard relationships use only explicitly public, source-bound verified facts or actor-stated claims, both for incident rows and alliance/opponent dimensions. The model boundary normalizes NFKC/control characters, detects role/tool/secret/policy directives, preserves safe neighboring evidence, and wraps research in explicit untrusted-data markers. Cross-line detection examines bounded adjacent windows (`backend/app/services/actor_role_prompt.py:104`, `backend/app/services/actor_role_prompt.py:133`, `backend/app/services/actor_role_prompt.py:259`). `compile_actor_role_prompt` renders full, balanced or emergency layouts while preserving both delimiters, action/plan/decision/knowledge/evidence/red-line policy. `SIM_ACTOR_ROLE_PROMPT_MAX_CHARS` defaults to 6,000 and clamps to 1,800–12,000.
