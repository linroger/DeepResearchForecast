Admission stores the actor-intelligence policy and `safety_policy_v1`; language preserves three states: default (`None`), automatic (`""`), or explicit override. The method returns the state immediately, including task and pipeline IDs (`backend/app/services/pipeline_orchestrator.py:7953`).

The weighted interval includes PREPARE (`backend/app/services/pipeline_orchestrator.py:8894`; `backend/app/services/pipeline_orchestrator.py:8904`).

The stage updater checks cancellation and the run interruption breaker before changing stage status/progress/message/start time, current stage, last progress and heartbeat, global progress, partial artifact registry, durable state, and the task's polling progress (`backend/app/services/pipeline_orchestrator.py:8949`). `_complete_stage` sets completion/progress/message, records artifacts, persists state and telemetry. ## Full `_run` execution

### Attempt setup and stage sequence

`_run` creates a fresh orchestrator instance, task manager and per-pipeline telemetry context, registers the interruption breaker/probe if enabled, captures the telemetry baseline, writes the reproducibility manifest and starts the independent heartbeat before entering the main try block (`backend/app/services/pipeline_orchestrator.py:11883`). Full execution is RESEARCH → ONTOLOGY → GRAPH → PREPARE → RUN → REPORT → optional ensemble → health gate → completed; research-only exits after RESEARCH. Static full-mode bands are 0–30, 30–40, 40–60, 60–72, 72–92 and 92–100; research-only uses 0–100 (`backend/app/services/pipeline_orchestrator.py:95`). The runner traverses the sequence on every attempt and chooses stage-specific reuse at each boundary, rather than jumping directly to `current_stage`.

### RESEARCH: choose reuse, recovery, single lane or parallel lanes

A report candidate needs an existing `research_report.md` with at least 400 stripped characters. With `research_contract_manifest.json`, both integrity and research-quality checks must pass; evidence-manifest presence requires the judge check. A failed contract/quality check selects synthesis-only recovery when `evidence_synthesis_manifest.json` exists. A manifest-less legacy candidate is reusable only when the RESEARCH stage was completed and direct `_validate_reuse` accepts it. An evidence manifest without a report also selects synthesis recovery. An uncompleted report with no contract is not reused (`backend/app/services/pipeline_orchestrator.py:11902`; `backend/app/services/pipeline_orchestrator.py:11919`). Reuse loads report/dossier/actors/sources/timeline through `_load_research_handoff`; that loader rejects short reports and treats a degraded dossier as absent (`backend/app/services/pipeline_orchestrator.py:3857`).

Otherwise the runner chooses synthesis recovery, or resolves the run's research engine and outer lane count. Multiple lanes use `_run_parallel_research_tracks`; a single lane validates prompt/depth/run/lane/attempt checkpoint lineage, activates/checks a bounded budget epoch, computes concurrency caps, and calls `DeerFlowResearchRunner.run` with the validated resume IDs, graph ID, language/depth/model, cancellation and PID/progress callbacks. After a newly run research path ends it clears research PID and track PID list (`backend/app/services/pipeline_orchestrator.py:11965`; `backend/app/services/pipeline_orchestrator.py:11995`; `backend/app/services/pipeline_orchestrator.py:12033`; `backend/app/services/pipeline_orchestrator.py:12076`).

Postprocessing reads the report/dossier/actors result. Optional lint is audit-only for judge-bound or manifest-less single-lane reports; accepted changes for other manifest-owned reports stay in memory until private-generation finalization. Language is explicit/default or inferred from CJK share. Cast reconciliation can mutate legacy actors, but sealed v1 actors receive a read-only duplicate audit; sealed-audit failure raises. Reconciliation audit/pointers and summary options are saved where applicable (`backend/app/services/pipeline_orchestrator.py:12079`; `backend/app/services/pipeline_orchestrator.py:12148`).

The runner ingests research telemetry, optionally warms embedding, surfaces research quality/budget, computes dossier coverage warnings, and attempts forecast-input compatibility injection. Sealed v1 actor data is preserved when forecast inputs are absent. `_finalize_research_contract` receives all sanctioned in-memory changes and effective ledger before stage completion; confidence penalty is then surfaced from finalized metadata. A full run calls `_enforce_actor_intelligence_reception` with actors, report, dossier, sources and handoff before declaring RESEARCH complete. Research-only skips that full-run reception call and completes the pipeline/task with the research report path (`backend/app/services/pipeline_orchestrator.py:12204`; `backend/app/services/pipeline_orchestrator.py:12235`; `backend/app/services/pipeline_orchestrator.py:12263`; `backend/app/services/pipeline_orchestrator.py:12294`). Contract files include report/dossier and coverage/judges, actor lineage, actors/sources/timeline/quantitative/contested/market histories, progress, metadata and charts index (`backend/app/services/pipeline_orchestrator.py:3140`).

### ONTOLOGY: project storage and generator inputs

An existing project with a truthy ontology is reused directly. Otherwise a missing project is created, its simulation requirement and extracted research report are saved, a report file descriptor/text length is recorded, and its ID is persisted in pipeline state. `OntologyGenerator.generate` takes the dossier first when nonempty, then the report, simulation prompt, actor context with optional dossier-derived seed block, `template=None`, central question and actors. Rich-schema mode preserves the full returned dictionary while normalizing entity/edge lists; the alternative retains only those lists. The project receives analysis summary and ONTOLOGY_GENERATED status. `handoff/ontology.json` is atomically written on a best-effort basis, then the stage completes (`backend/app/services/pipeline_orchestrator.py:12307`).

### GRAPH: reuse or build, then protect actor seed projection

Reuse requires a completed GRAPH stage and graph ID from state/project, artifact-integrity acceptance, sealed-v1 seed-manifest readback validation when applicable, and a successful defined-entity query with nonzero entities. Failure records a `resumed_stage_validation` reason and rebuilds. Successful reuse records the ID, best-effort re-registers ontology in process memory, and preserves stage timing (`backend/app/services/pipeline_orchestrator.py:12389`; `backend/app/services/pipeline_orchestrator.py:12402`; `backend/app/services/pipeline_orchestrator.py:12427`).

Build obtains report and optional dossier chunks through `_graph_research_chunks`; `GRAPH_CHUNK_SOURCE` selects dossier-only, report-only, or dossier-before-report. It updates dynamic bands, creates a graph, attempts ontology registration with text-extraction fallback, validates/parses the research as-of anchor, seeds actors/relationships, and calls `_validate_actor_graph_seed_contract(phase="post_seed", persist=True)` (`backend/app/services/pipeline_orchestrator.py:12456`; `backend/app/services/pipeline_orchestrator.py:12484`; `backend/app/services/pipeline_orchestrator.py:12512`). `add_text_batches` uses batch size ten and the as-of reference time, records ingest loss/degradation, and waits for episode completion (`backend/app/services/pipeline_orchestrator.py:12544`).

Optional community detection writes `communities.json` for subsequent summary/config consumers; entity resolution can write `entity_merges.json`; pruning writes `graph_prune.json` and summary options. After these mutations the actor seed projection is revalidated with the persisted expected manifest (`backend/app/services/pipeline_orchestrator.py:12574`; `backend/app/services/pipeline_orchestrator.py:12590`; `backend/app/services/pipeline_orchestrator.py:12611`; `backend/app/services/pipeline_orchestrator.py:12639`). Concurrent graph builds can expose duplicate-name counts. Structural inspection records node/edge/component metrics, writes alias-folded `graph_priors.json` and optional `graph_priors_structural.json`, then saves the project GRAPH_COMPLETED status and pipeline graph ID before completing GRAPH (`backend/app/services/pipeline_orchestrator.py:12653`; `backend/app/services/pipeline_orchestrator.py:12687`; `backend/app/services/pipeline_orchestrator.py:12727`). Community/resolution/prune/metric failures are normally logged and skipped; explicit actor-seed validation lies outside those best-effort blocks.

### PREPARE: current simulation, final config bytes and seal

Reuse requires completed PREPARE, an existing simulation, artifact validation and `validate_prepared_simulation_config`; failed seal validation records artifact and rebuild reasons. A new attempt creates a dual-platform simulation, replaces pipeline simulation ID, removes partial pointers, reads optional graph priors and calls `prepare_simulation` with prompt, report, actors, priors, research language, round budget and progress callback. Persona concurrency is selected from the configured parallel count or the bounded alternative; calendar mode passes only explicit round limits into preparation (`backend/app/services/pipeline_orchestrator.py:12733`; `backend/app/services/pipeline_orchestrator.py:12775`; `backend/app/services/pipeline_orchestrator.py:12809`).

Before any config additions, a reused PREPARE with missing RUN-completed stage may qualify through `_completed_sim_reusable` and RUN artifact checks; otherwise the ordinary completed-RUN path requires `_run_reuse_ready` and RUN artifact checks. Either result sets `_run_already_done`, preserving sealed bytes. Other paths can apply the scenario overlay and inject a world-state seed when calendar mode or the decision-channel flag permits. The seed uses actors, as-of and inferred horizon, overridden by calendar configuration's horizon/source/defaulted fields. These additions are best-effort; any actual config mutation requires `reseal_simulation_config`, whose failure propagates. ### RUN: execute or reuse, publish summary, require completion evidence

Ordinary RUN reuse requires reused PREPARE, a prior completed RUN, matching completed simulation/summary, and current integrity validation. Rebuilt PREPARE invalidates old RUN reuse. Separately, the disk-completed path from PREPARE can recover lost RUN stage flags and records `run_reused_completed_simulation` (`backend/app/services/pipeline_orchestrator.py:12940`).

A fresh RUN starts `SimulationRunner.start_simulation(platform="parallel")` with explicit/non-calendar default rounds and pinned optional graph-feedback settings. Polling checks cancellation, missing state, COMPLETED, FAILED/STOPPED, and elapsed stagnation. Changed `(current_round,total_rounds)` updates progress; the first known total also updates dynamic bands/run manifest with calendar fingerprints. The independent disk watchdog runs alongside the poll loop and is retired on every exit; a poll exception first ingests simulation telemetry. Cancellation attempts to stop the simulation; inline stagnation also attempts a stop before raising. Polling sleeps five seconds between checks (`backend/app/services/pipeline_orchestrator.py:12974`; `backend/app/services/pipeline_orchestrator.py:13005`; `backend/app/services/pipeline_orchestrator.py:13062`). Enabled graph feedback adds a monitor join (30-second timeout warning) and updater drain before summary/report work (`backend/app/services/pipeline_orchestrator.py:13082`).

Both fresh and reused paths read optional communities, publish/preserve or backfill `run_summary.json`, ingest simulation telemetry, and require enabled-lane completion evidence plus a valid published summary. Summary publication exceptions are logged but leave the hard completion gate unsatisfied. The runner then best-effort projects terminal round/platform/error fields into simulation state, completes RUN with the appropriate reused timing, and records decision-channel observations (`backend/app/services/pipeline_orchestrator.py:13099`; `backend/app/services/pipeline_orchestrator.py:13119`; `backend/app/services/pipeline_orchestrator.py:13138`; `backend/app/services/pipeline_orchestrator.py:13168`).

## Parallel research and synthesis recovery

`_run_parallel_research_tracks(state, handoff_dir, upd, n_tracks)` slices the configured angle list, resolves the run's research engine, and enables global synthesis only with multiple angles and its feature flag. Helper-derived outer workers, per-lane subagents and global model concurrency bound fan-out. A shared budget DB/telemetry/epoch is activated and checked before lane launch; exhaustion stops with an explicit-resume requirement. Bridge synchronization happens before submitting any lane (`backend/app/services/pipeline_orchestrator.py:11060`).

Per-lane progress is monotonic and capped at 95; aggregation excludes failed lanes and serializes publication, updating only on changed aggregate percentage or a 15-second refresh. Spawn callbacks persist all lane PIDs and retain the first in `research_pid`. Each `track_<k>` run validates checkpoint lineage against its prompt, depth, run/lane identity and allowed attempt IDs; passes shared budget, validated resume/checkpoint IDs, concurrency, graph ID, and the original prompt prefixed by the lane angle. The baseline lane owns dual-track actor research; `shared_actor_track=False`; `evidence_only` follows global synthesis. Nonzero exits are lane failures (`backend/app/services/pipeline_orchestrator.py:11124`; `backend/app/services/pipeline_orchestrator.py:11162`; `backend/app/services/pipeline_orchestrator.py:11175`).

The executor waits for every future. Cancellation propagates; individual ordinary failures are recorded/excluded from progress. No survivors fails RESEARCH. Survivors are sorted by lane index, and `merge_sources_union` supplies a deterministic global ledger. Fewer survivors than requested marks degradation (`backend/app/services/pipeline_orchestrator.py:11241`).

### Evidence lanes followed by global synthesis

This branch requires surviving baseline index zero and its fresh nonempty shared dossier; a nonbaseline dossier is rejected. Every surviving lane must have nonempty `evidence_pack.md` and `sources.json`, parseable source lists, and at least one HTTP(S) source whose `reachable` field is not false. The parent writes `evidence_synthesis_manifest.json` version 3 with relative lane pack/ledger paths, bytes and SHA-256; merged sources/count/canonical hash; and a baseline actor descriptor (`backend/app/services/pipeline_orchestrator.py:11279`; `backend/app/services/pipeline_orchestrator.py:11308`).

## Health, observability, and recoverable stops

The independent RUN watchdog reads disk `run_state.json` every 30 seconds, exits on its completed/error signal, tracks round changes, and attempts to stop a simulation after configured stagnation. The caller stops the watchdog with its control dictionary; a nonpositive stall interval disables it (`backend/app/services/pipeline_orchestrator.py:9113`).

Report health counts section files and placeholders: the generation-failure template is a placeholder; a section shorter than 200 characters also counts unless it contains image/SVG/Mermaid markers. It accepts forecast scenarios or binary forecasts, surfaces forecast quality findings, and, when final-audit checking is enabled, requires a nonempty audit with the configured policy version, explicit hard pass and disk-memory identity, passing enabled publication gate, valid required structured forecast/scenario contract, and matching markdown/forecast hashes. All-placeholder sections, missing required structured forecast, a nonzero report smaller than 2,000 bytes, or hard audit/quality findings yield failed health; partial placeholders and other quality findings yield degraded (`backend/app/services/pipeline_orchestrator.py:9161`; `backend/app/services/pipeline_orchestrator.py:9250`; `backend/app/services/pipeline_orchestrator.py:9324`).

RUN health reads post/comment row counts from available simulation SQLite files in read-only mode, preferring integer `run_summary.organic_action_count` over raw DB rows. It surfaces summary health, runner error, truncated round coverage, zero organic actions when a DB exists, and graph-feedback dead-letter line counts; these yield degraded health rather than a hard failure (`backend/app/services/pipeline_orchestrator.py:9351`). `_enforce_pipeline_health` aggregates report, run, graph-ingest skipped ratio and degraded prune evidence into `options.pipeline_health`, propagates run caveats to the RUN stage error field, and raises only for report hard issues. An assessment exception is logged and ignored; a disabled gate returns immediately (`backend/app/services/pipeline_orchestrator.py:9445`).

`_fail_stage` marks the current stage failed and timestamps it, saving state and telemetry. The interruption-halt helper records a failed pipeline/current stage, a breaker snapshot with halted stage/time and resume endpoint in `options.provider_outage_halt`, and a failed task. It uses the ordinary resume/checkpoint path (`backend/app/services/pipeline_orchestrator.py:9757`; `backend/app/services/pipeline_orchestrator.py:9766`). This study describes that existing stopping path without contacting external services.

Partial-artifact discovery uses nonempty file metadata and a `provisional` marker, including research progress log, RUN state/platform action logs, report sections, stage chart assets, and research CSV datasets.
