## 5) Findings, Decisions, Assumptions
- **F1 (real reports, read-only):** in the 9 latest v3 reports with method skills (`backend/uploads/pipelines/pipe_*/handoff/research_report.md`: USD/JPY, Brent Q2 2027, German politics, OPEC+, Japan leadership, France budget crisis, India macro, Burnham agenda, US–China trade) almost every line that pairs a probability word with a percentage and a marker outside the scenario section is a scenario weight, an outcome probability or a market quote, not the probability of an exogenous event (scan: `scan_reports.py` / `real_report_scan.txt` in the evidence dir). Consequence: on many live questions the honest result is `risks: []` and the seed keeps recording `no_documented_shocks`. Shocks fire on live runs only when the research itself documents event hazards (see §9, research of hazards).
- **F2 (merge integration):** `main` 303e5a8 added "The consequence arbiter must confirm delivery." to the actor decision prompt. The world-paths loop harness (`_PathLLM`, from the merged branch) tested "consequence arbiter" before its parent's decision branch, so every decision call (temperature 0.4) counted as an arbiter call → 3 failures in `test_world_paths.py` on the merge. Fixed in the test only: this session first checked the decision marker first (d51fb55, as the other world harnesses do); the world-v1 session, merging the same branch for `main` (its run `/Users/rogerlin/Downloads/drf-guarded-runs/20261021-012317-merge-paths-plain/` shows the same 3 failures), fixed it by matching the arbiter prompt's opening sentence (33ae24d). The branch now carries 33ae24d only, so a later merge into `main` meets one fix, not two.
- **D1 (verification is line-based):** the probability, its window and its marker must stand on one report line that also names the event (a word of ≥ 3 letters other than generic ones, or two consecutive CJK characters). LLM report paragraphs are single lines, and the writer rules put a marker in every paragraph that states a number, so a line is the unit of "this statement". A paraphrased window ("per year" for "annual") is therefore blanked — the seed records `shock_without_window` — which costs yield but never invents a hazard. Alternatives rejected: whole-report containment (a 5% stated for one event vouched for another in the first probe), sentence splitting (fragile across EN/ZH punctuation).
- **D2 (what fails is blanked, not guessed):** an unverifiable window or source is left `""` so the seed's own typed gap names it (`shock_without_window` / `shock_without_source`); a risk whose probability no line states for that event is dropped (it is not a documented risk). An effect size the report does not state is dropped and the sign kept as a direction, so the arbiter sizes it (`shock_effect_direction_only`).
- **D3 (effects bind by exact name):** an effect binds to a `quantitative_facts` metric by equal name keys, the longest metric name inside the effect's, or a unique containment / word-subset match ("Brent price" → "Brent crude price"; "crude price" with Brent and WTI → none); it then carries the metric's exact name, so the seed binds it by equality. The frame and facts extractions run in parallel, so the frame model cannot see the metric list; running frame after facts would raise binding but add one extraction call's latency and couple the two caches — left for after the live check measures `effects_untracked`.
- **D4 (source text):** `source` is "<source title> [S<n>]" (the marker resolved positionally into `sources.json`, as `normalize_quant` does), plus `source_url` and `tier`; the marker alone would be meaningless inside the simulation, where the seed and the arbiter quote it.
- **D5 (no required key, no new call):** `risks` is not a required key of the frame reply, so a frame cached by an earlier attempt or an older-shape reply parses without a retry and yields `[]`; the frame is still one call in the same fan-out after the shared prime, with only its task text longer.
- **D6 (scenarios):** the frame's scenarios are the share prior. Exact-name equality alone missed paraphrases in the real reports (F1: "Coalition rupture and early election — 25%"), so a risk whose stated probability is a scenario's own weight on lines that name that scenario is dropped too.
- **Assumption A1 (tested live, partly holds):** the frame model copies probabilities and windows verbatim often enough for the line checks to keep documented risks. Measured on `pipe_fef5312f76f0` (F3). A single probability was copied exactly ("5%"), and the source marker was right. A window was paraphrased ("2026 Atlantic hurricane season" for the line's "Residual hurricane season" / "To 30 Nov 2026"). Three window-specific probabilities were packed into one string (F4).
- **F3 (live counts, `pipe_fef5312f76f0`):** `meta.forecast_risks` = extracted 5, kept 1, `probability_not_stated` 4, `window_not_stated` 1, `source_not_stated` 0, `scenario` 0, `effects_untracked` 1, `effects_kept` 0. Per row:
  - Kept: "Above-normal 2026 Atlantic hurricane season activity" "5%", `[S34]` (NOAA, tier S1); report line 175 states it: "NOAA's 6 Aug 2026 outlook: 75% below-normal, 20% near-normal, 5% above-normal activity … [S34][S47]". Its window was blanked (paraphrase, above). Its effect "LNG terminal feedgas (about 18.2 Bcf/d)" bound to no `quantitative_facts` metric (the facts extraction calls it "US LNG feedgas"): D3's parallel-extraction limit, one more data point.
  - Dropped: three rows with an empty probability, honestly undocumented (January freeze-off, extended LNG outage, November Gulf landfall). They count as `probability_not_stated` together with the El Niño row (F4), so that count mixes "no probability given" with "probability not found".
  - Read per §9: no invented probability passed, no scenario was offered as a risk, sources were right; the losses are F4 (format) and the window paraphrase.
- **F4 (false negative: compound probability):** the model returned the El Niño risk ("Historic-strength El Nino event (3-month RONI of +2.5C or higher)", `[S6]`) with `probability` = "54% (Sep-Nov 2026); 83% (Oct-Dec); 70% (Nov-Jan)" and `per` = "per three-month window as stated". `_probability_phrases` keeps a string probability whole, so that whole string had to stand on one line. - **F5 (seed: calendar windows unreadable):** `world_model_seed.parse_risk_window` reads counted units ("within 9 months"), unit words ("per year", "annual", "monthly") and "horizon" only. Season and calendar-range windows, the form NOAA CPC and NOAA hurricane outlooks use, all give `None` → `shock_without_window`. Rejected forms: "October–December 2026", "December–February 2026-27", "DJF", "winter 2026-27", "through the 2026 hurricane season", "by 31 March 2027", "this winter", "per season". So even F4's split rows give 0 shocks (`replay.txt`). A calendar window also has a position in time ("September–November" had mostly elapsed at the seed's as-of date, 2026-10-20), which a duration-only constant hazard cannot express.
- **F6 (§9 item 4 was worded wrongly):** `seed_gaps` adds `no_documented_shocks` whenever the seed admits no shock, also when a kept risk became a typed `shock_*` gap. Live: kept 1 → `shock_without_window` + `no_documented_shocks`. The check is "absent iff a shock was admitted" (§9 corrected).

A worktree whose `backend/uploads` is a symlink to the deployment's uploads therefore fails right after the research subprocess, with `NotADirectoryError: 'uploads'` → "research root must not contain parent traversal". All research artifacts are written first, but the research contract is not.
